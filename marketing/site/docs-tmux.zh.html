文档

使用 tmux

Offhook 以 tmux 控制客户端的身份 attach 上去，把你的 session、window、pane 用原生 iOS 视图画出来。这页讲清楚三件事：它做了什么、在你服务器上改了什么、以及到哪儿为止。

前提是主机上有 tmux，在 PATH 里——或者你在连接表单的 Custom tmux Path 里填了路径。没别的了。下面装 hook 那节是可选的， 跟连接本身无关。

没有 tmux 的话，连接不会失败，只会降级：一个纯 SSH 的单 pane，加一条横幅 “tmux not found on this host — plain SSH session.”，旁边的 Install tmux 会按你的包管理器把命令摆出来，你点了才执行。Offhook 绝不会偷偷把你切到另一个多路复用器 ——tmux 和 herdr 各自持有互不相干的 session。另外，一旦你填了自定义 tmux 路径，这套探测整个 跳过：探测只走 PATH，而你亲手填路径本身就是为那个二进制背书。

只往登录 shell 里写一行

Offhook 不是把 tmux 那套字符界面塞进一块小屏幕，而是以控制客户端的身份 attach——tmux -CC，跟 iTerm2 用的是同一套控制模式——然后自己渲染。连上那一刻 写进去的就是这行：

tmux set -g history-limit 50000 2>/dev/null; tmux -CC attach

attach 不带 -t，接的是你最近用过的那个已有 session。 Offhook 自己绝不执行 tmux new。服务器上一个 session 都没有时，你看到的是 一个把话说明白的空状态，和一颗要你自己按的 Create Session。

发现（discovery）是同一条通道上的三条命令，树有变动就重跑。-a 是服务器上的全部 session，所以首页那棵树能同时展开好几个：

list-sessions -F '#{session_id} #{session_attached} #{session_name}'
list-windows -a -F '#{session_id} #{window_id} #{window_index} #{window_layout} …'
list-panes   -a -F '#{pane_id} #{window_id} #{pane_index} … #{pane_current_command}'
  • attach 有 22 秒的期限。tmux 一直不确认，首页卡片就变成 stalled， 并给出「Attach didn't complete — tmux never confirmed.」和一颗重试。注意这时 SSH 本身是活的， 没接上的是 tmux 这一握手。
  • 控制模式跑不了 mosh。mosh 传的是屏幕差分，不是按行分帧的协议流。所以 mosh + tmux 这条路上，Offhook 在 mosh 里渲染 tmux 原本那套全屏界面，同时另开一条 sidecar SSH 连接跑 -CC，只为喂饱面包屑和那几个面板。这条 SSH 连不上， 你拿到的就是一个光秃秃的 tmux attach，一个原生面板都没有。

怎么走动

永远只有一个 pane，占满整屏

Offhook 只显示一个 pane，并且替你 zoom（select-pane -Z； window 有分屏且没 zoom 时再补一条 resize-pane -Z）。分屏永远不会并排画出来， 而且你离开的时候 zoom 是留在那儿的——分屏布局不归 Offhook 打理，prefix z 在哪儿都能变回来。真实的分屏几何只有 Select Pane 面板里看得到。

顶栏是三段可点的面包屑——session › window › pane，各开各的面板。pane 那一段的 文字优先级是：hook 打上的 agent 名 → pane 的前台命令 → pane 2。

面板列出什么底部提示
Sessions 服务器上的全部 session：当前那个显示 3 windows · 2:logs， 其余显示 attached / detached Swipe to switch · ⌃ b s
Windows 当前 session 的 window，形如 2 panes · nvim，带 agent 圆点以及圆点的文字标签——只靠颜色不算把话说清楚 Swipe to switch · ⌃ 1-9
Select Pane 按 tmux 自己的 layout 字符串解析出的真实布局树，按比例画；每格显示 window 内的 pane 序号和它的命令 Tap to focus · ＋ splits a new pane · ⌃ b q

限制：Windows 面板只列当前 session 的 window，别的 session 要去首页 那棵树里找。底部那几颗键位印的是你自己那台 tmux 的绑定，方便你在主机上用实体键盘 做同样的事；按多路复用器分开印是因为 ⌃ b q 在 tmux 里是列 pane，在 herdr 里是断开。

滑动

一根手指，两个方向

终端上就一个 pan 手势，两个轴都归它管。拖过大约 12 pt 后按累计位移锁定方向； 横向滑到 40 pt 才算数，同时给一次触感反馈。

  • 左滑下一个、右滑上一个，到头会绕回来
  • 当前 window 里有多个 pane 就在 pane 之间循环；只有一个，就在这个 session 的 window 之间循环
  • SSH + tmux 和 mosh + tmux 都能用（后者走 sidecar 转发）。herdr 上没有 接这个手势，所以 herdr 的面板印的是「Tap to switch」

新建与销毁

新建走面板标题栏或首页 SESSIONS 那一行的 +；重命名和销毁在任意 一行长按出来的菜单里。名字发出去之前会加单引号，所以叫 my project 的 session 也能正常处理。

动作Offhook 发出去的命令说明
新建 session new-session -d -P -F '#{session_id}' 然后立刻切过去。点了 Create 还留在原地，读起来就是「啥也没发生」。
新建 window new-window -P -F '#{window_id}' 输入框是 Name (optional)——「Leave blank to let the program name it.」
新建 pane split-window，紧接 resize-pane -Z 分出来那一刻就被 zoom 回单个整屏 pane。
重命名 rename-session / rename-window tmux 的 pane 本来就没有名字，所以 pane 没有重命名这一项。
销毁 kill-session / kill-window / kill-pane 确认框把后果写明白：「Kill window 2: logs? Every pane in it dies.」

销毁最后一个 session 会让 tmux server 退出，控制通道跟着断，所以 Offhook 先在本地把树剪掉，免得界面卡在那儿等一条永远不回来的回复。tmux 拒绝执行时—— 比如 session 重名——你会看到 tmux 自己的报错原文，停三秒。没有一条错误被吞掉。

Scrollback

「往上滚」其实是两件不同的事

pane 的历史在服务器上，App 本地留下的只是 tmux 重绘过的内容。所以往上滑属于 哪一种，Offhook 是去问 tmux 的：对当前 pane 执行 display-message -p '#{mouse_any_flag}'，每次切换、每次开始滚动都重新读。 问而不猜，是因为在 mouse on 之下渲染出来的终端根本判断不了。

程序抢走了鼠标——Claude Code、vim --mouse、less --mouse

Offhook 合成滚轮事件送进这个 pane，让程序自己滚：tmux 不会进 copy-mode， 滚完照样能打字。一次挥动最多 6 个事件。

ESC [ < 64 ; col ; row M   # 向上，看更早的内容
ESC [ < 65 ; col ; row M   # 向下，回到更新的内容

普通 shell

走 tmux 的 copy-mode（复制模式），命令从控制通道发，节流到每 0.18 秒一步。 任何一次按键都会先发 -X cancel，所以打字永远能把你带回最底下的实时行—— 也因此没先往上滚过，往下滚是没反应的：还没进 copy-mode，无处可往下。

copy-mode -t %41
send-keys -t %41 -N 3 -X scroll-up

你到底能往上翻到哪儿

attach 的时候，Offhook 会把这个 pane 已有的历史回灌一次 （capture-pane -e -S -2000 -E -1），最多 2 000 行，而且只对主屏幕 (primary screen) 的 pane 做。处在备用屏幕 (alternate screen) 的 pane——vim、top、Claude Code——只拿到当前可见的那一帧：纯文本 dump 里没有光标定位，倒进全屏程序会把它冲烂。

所以刚 attach 上的那个 Claude Code pane，本地在提示符之上是空的。往上滚仍然 能用——那是通过 copy-mode 去翻 tmux 自己的历史——但目前还没有「翻到顶再按需拉更多」这个 能力。这是真实的缺口，不是你哪个开关没打开。服务端历史在 attach 时被抬到 50 000 行， 客户端每个 pane 也留 50 000 行；2 000 只是回灌的深度。

如果终端上的滑动跟你跑的程序打架，快捷键栏里的 ⇅ Scroll history 能干同样的活儿。它是内置项，但默认不在栏里。

前缀键

SSH + tmux 下，Ctrl-b 到不了 tmux

按键是按 pane 作为 tmux 命令投递的，字节直接注进那个 pane 里跑着的程序：

send-keys -t %41 -H 1b 5b 41

这条路上没有任何一环会去查 tmux 的键表，所以你敲的 ^B 就是以 ^B 的身份到达你的 shell 或 agent，它不会打开前缀。导航请用面包屑、三个面板、 首页那棵树和滑动。要从软键盘发控制键，用 ctrl 那颗键：它是一次性的，按下之后 你敲的下一个键会以对应的控制码发出去。

mosh + tmux 恰好反过来。屏幕上就是 tmux 自己的界面， Ctrl-b 跟你在桌面上用得一模一样——也正因如此，那条路上的面包屑会退化成 user@host · tmux。有个尖角：自定义快捷键勾了 Only in tmux 之后， 过滤看的是 SSH + tmux 的控制器，所以它在 mosh + tmux 的会话里不会出现。

tmux 上的 agent 状态

不装 hook 是猜，装了才是知道。

herdr 把 agent 状态做成了协议字段，主机上什么都不用装。tmux 没有这个字段， 所以 Offhook 提供一套 hook 安装——并且老实承认：这是要你自己动手装的，装之前它先给你的配置 做备份。

打开那个面板

设置 → Install agent hooks。选你的 agent：Claude Code、Codex、Gemini CLI、Qwen Code、Qoder、Factory、CodeBuddy。herdr 连接上这一行直接隐藏——用不着。

把那行命令跑掉

Run in terminal，或 Copy command 自己贴。它先把配置复制成一份带时间戳 的备份，写入 ~/.offhook/offhook-stamp.sh，再合并四组 hook。

跑一轮，再 Re-check

hook 只在 agent 的一轮里触发，没跑之前什么都不会出现。跑完点 Re-check 确认：「Hooks are live」。

hook 到底写了什么

往 $TMUX_PANE 上写四个 tmux pane 选项。机制就这些——没有 socket、没有守护进程、没有任何回调打给 Offhook。

tmux set -p -t "$TMUX_PANE" @offhook_state working   # 或 attention | done
tmux set -p -t "$TMUX_PANE" @offhook_agent claude
tmux set -p -t "$TMUX_PANE" @offhook_since 1754630400
tmux set -p -t "$TMUX_PANE" @offhook_title "Bash: npm install"

映射是：UserPromptSubmit 和 PreToolUse → working；Notification（Claude 系）或 PermissionRequest （Codex）→ attention；Stop → done。脚本第一行是 [ -n "$TMUX" ] || exit 0，而且永远 exit 0——它只给 pane 打个戳，不可能挡住、 拖慢或打断 agent。重复跑安装命令是去重，不是往上叠。

Offhook 在附着期间每两秒读回一次。没设过的选项展开是空串，所以没被打戳的 pane 回来长这样 %5||||，然后落到下面那套猜测里：

list-panes -a -F '#{pane_id}|#{@offhook_state}|#{@offhook_agent}|#{@offhook_since}|#{@offhook_title}'
不装的话，你少了什么

兜底那套是猜的，而且故意收得很窄

没有 hook 时，Offhook 只能读 pane：已知 agent 命令下持续有输出满 2 秒 → working； 终端响铃 (BEL) → 需要你；安静 4 秒 → done，25 秒后这一行消失。

  • 只有 claude、codex、gemini、 qwen、qoder、factory、 codebuddy、aider、goose、 opencode 会因为输出被提升。构建、tail -f、dev server 和 vim 永远不会被当成 agent——只有 BEL 能绕过这层过滤
  • 没有细节行。「Bash: npm install」来自 @offhook_title； 猜的那套根本不知道 agent 在问什么
  • 没有「跑完了」那一声。done 通知只在真收到 Stop 戳时才发 ——「安静了四秒」这种模糊程度，不配震你一下手机

依赖它之前，先知道这些限制

  • Gemini CLI 没有 Notification 这个事件，在它这儿「需要你」只能退回 到响铃那套。
  • 主机上没有 jq 就没有 title。状态照样打戳。
  • 当前 pane 正在跑 agent 时，Run in terminal 会拒绝执行——那条命令会被打进 agent 的输入框。它会明说，并让你先切到一个 shell pane。
  • tmux 连接的首页没有 Agents 列表。那一节只在 herdr 上有：hook 的覆盖度只等于 你装了多少，而一个会默默漏掉一半 agent 的列表，比没有列表更糟。
  • mosh + tmux 上，agent 状态根本到不了灵动岛。-CC sidecar 只驱动 面包屑和面板，没有接到 agent 监控上。想让手机告诉你 agent 在等人，请用 SSH + tmux。
  • iOS 会把 App 挂起，那两秒一次的轮询也跟着停。在你回到 App 之前，状态不会再更新。 Offhook 没有服务器，也没有推送——这就是「中间什么都不放」的代价。Live Activity 会在 120 秒后把自己标记为过期，显示 paused，而不是给你看一个冻住的「working」。

在你的服务器上

它附着到你已有的东西，但没做到「什么都没碰」。

Offhook 不会替你创建 session，也不会改它的样式。但说「什么都不改」就是撒谎， 所以这里是连着的时候它确实改动的全部清单。

全局

history-limit

每次 attach 之前都会先跑 tmux set -g history-limit 50000，SSH 路径和 mosh sidecar 都一样。这是服务器级选项；按 tmux 的语义，它作用于之后新建的 pane。

按 window

尺寸钉死

你在看某个 window 时，resize-window -x -y 会把它钉到手机的字符网格上， 好让全屏程序重排。同一时间看这个 window 的其他客户端，也会被拿到手机的宽度。

会还回去

……然后解钉

离开这个 window 时、App 进后台时、断开时都会还。光发 resize-window -A 不够——那只是改钉到「最大的那个客户端」。

留着不动

Zoom

当前 pane 是 zoom 状态，你离开之后它还是 zoom。刻意的：分屏布局是你的， prefix z 在哪儿都能还原。

临时

copy-mode

你滚动和打字的过程里，pane 会被进出 copy-mode；另外 attach 后第一次看到某个 pane 时，会一次性取消它遗留的 copy-mode。

仅 mosh

状态栏

在 sidecar 这条路上，它附着的那个 session 会被设成 status off， 直到你切走或断开才还原。纯 SSH + tmux 下，你 session 的外观不会被动任何一处。

同一条原则的另一半：别的客户端切它自己的 window，绝不会把你手机的 视图拖着走，除非你正在看的那个 window 已经没了。而如果一台开着 window-size latest 的桌面客户端跟你抢尺寸，Offhook 会退让——5 秒内抢回 3 次 就停手 5 秒。你换来的是一块稳定的屏幕，代价是那一小会儿桌面端赢。
