Docs

在锁屏上回应 agent

服务器上的 agent 停下来问你要不要放行。这一页把整条链路讲清楚：那个状态怎么到你手机上、 每个按钮按下去实际往 pane 里打了什么、哪些开关能改它，以及 iOS 会在哪一步把这一切停掉。

agent 上报状态

用 herdr 时，agent_status 本来就是每个 pane 上的协议字段，主机上什么都不用装。 用 tmux 时，你装的 hook 会往 agent 所在的 pane 上盖四个 @offhook_* 选项。

Offhook 去读

只要 Offhook 还活着，它每 2s 扫一遍所有被跟踪的 session。herdr 的控制面轮询在有变化时是 2s，树一安静下来就退到 8s。

你这一下打回去

锁屏上的按钮跑在 Offhook 进程里，不在小组件里。每个按钮往那个 pane 发一串原始字节——Enter、Esc、 Ctrl-C，或者你输的文字。就这些，没有别的。

这张图里没有 Offhook 的服务器。你手机上的每一条提醒，都是正在运行的 App 从活着的会话里读出来、 在本机生成的本地通知。这是"中间不放任何东西"换来的，代价你在依赖它之前应该先知道。

把手机揣兜里走人之前，先看 哪些情况下它不管用。

状态来源

状态到手机上，有两条路

两条路最后落到同样四个词——工作中、需要你、已完成、空闲——但走法很不一样， 差别你是看得见的。

herdr

协议字段 · 主机零安装

  • agent 状态是协议字段：每个 pane 自带，主机上什么都不用装
  • blocked 对应"需要你"，working、done、idle 一一对上
  • 其余的值（包括 unknown）一律不产生状态，没有理由的东西不会亮
  • herdr 连接下设置里不显示 hook 安装那一行，因为没什么可装的
  • 不带状态切换的时间戳，计时从 Offhook 第一次看见那次变化开始，不是从它真正发生开始

tmux

要装 hook · 每个 agent 装一次

  • 一条命令，在设置里给你：Install agent hooks，配 Run in terminal、Copy command、 Re-check 三个按钮
  • 覆盖 Claude Code、Codex、Gemini CLI、Qwen Code、Qoder、Factory、CodeBuddy 七个
  • 重复跑没关系：先备份你的配置，脚本永远 exit 0 卡不住 agent，重复跑会去重
  • 不装就只能靠输出和终端响铃去猜——这一页下面会说清楚它有多粗

tmux 那条命令到底写了什么

一个共用脚本，加上在 agent 自己的配置文件里注册一次。动手改之前，你的配置会先被复制成一份带 时间戳的 .offhook.bak。

# 只写一次，所有 agent 共用
~/.offhook/offhook-stamp.sh

# 注册进 agent 自己的配置（这里以 Claude Code 为例）
~/.claude/settings.json
~/.claude/settings.json.offhook.bak.1754630400   <- 先备份你的文件

# hook 事件 → 盖上去的状态
UserPromptSubmit   →  working
PreToolUse         →  working
Notification       →  attention      （Codex 是 PermissionRequest）
Stop               →  done

每次触发盖四个 tmux pane 选项。Offhook 一次轮询只用一条 list-panes -a 全读回来——不管你开了多少 pane，都只有一个来回。

@offhook_state   attention
@offhook_agent   claude
@offhook_since   1754630400        （unix 秒）
@offhook_title   Bash: npm install --save-dev vitest    （最多 80 字符）

四项里只有 title 会单独失败：它靠 jq 从 hook 的 stdin 里抽出来， 所以主机上没装 jq 时状态照常，只是少了"它到底在问什么"那一行。done 时会清掉， 不会留一条过期的挂在那儿。还有一个坑值得知道：Gemini CLI 根本没有 Notification 这个事件，所以在 Gemini 上那组 hook 是空转的，"需要你"要靠终端响铃兜底。

tmux 上不装 hook？那就是在猜，而且它自己承认

什么都不装时，Offhook 盯的是 pane 的输出和终端响铃（BEL）。它故意做得很保守： 只有前台命令在一份固定名单里——Claude Code、Codex、Gemini、Qwen、Qoder、Factory、CodeBuddy、 aider、goose、opencode——而且要持续输出满 2 秒，才会冒出一行。编译、tail、跑着的服务永远不会被提上来。 安静 4 秒判为已完成，再过 25 秒这一行就消失。

这个猜法做不到的事：它没有 detail 那一行——Bash: npm install 这种内容只有 hook 和 herdr 两条路上才有；而且它认定的"完成"太糊，不足以拿来发完成提醒。 响铃则总会浮上来，哪怕响的是一个 shell 提示符。另外，一旦某个 pane 收到了真的 hook 戳记， 这个猜法对它就不再起作用。

herdr 上永远不跑这套启发式。herdr 报的是事实，在事实上再叠一层猜测， 只会是一个更差的第二意见在跟真相打架。

呈现

锁屏上真正出现的东西

整个 App 只有一个 Live Activity，不是每个连接一个。它最多带 4 个 agent， 最急的排最前：需要你 → 工作中 → 已完成 → 空闲。

头一行是计数 左边是 Offhook，右边是按实时计数拼出来的一句话——1 needs you · 1 working。 已完成的也算在里面。

只有最急的那个带按钮 状态点、命令名、host · session · window、它在问什么，加上那排按钮。 它下面的全部收成一行——因为 iOS 会把过高的 Live Activity 裁掉， 当初被裁掉的正好就是第二个 agent 的 Allow 和 Deny。

计时是实时走的 工作中和需要你的行，从状态变化那一刻起往上数。已完成和空闲显示的是状态词，不是时间。

把同一张卡片写成文字示意图，结构就没有歧义了。 第二个 agent 没有 detail 行、也没有按钮，这是有意的：

Offhook                              1 needs you · 1 working

●  claude                                       04:11
   work · main · 2:rednote
   Bash: npm install --save-dev vitest
   [ Allow ]  [ Deny ]  [ yes ]  [ continue ]

●  codex                                        1:22:07
   work · api · 1:server

灵动岛上

胶囊里一次只显示一个 agent——这是 iOS 的限制，不是我们的选择。多个 agent 同时活着时， 展开态里有一个 Switch 按钮，用来轮换胶囊显示的是哪一个。点这张卡片的任意位置， 会直接跳进那个 pane。

  • 收起态：左边是状态点。右边：只有一个 agent 被挡住时是一个琥珀色 !， 多个时是琥珀色数字；正好一个 agent 在工作时是一个青色的实时计时；有一个完成时是一个对勾。
  • 展开态：头条 agent 带 detail 行，然后最多再来两行带各自的状态点和计时， 然后 +N more，最后是那排按钮。

needs you 只要有人卡在等你，胶囊就归琥珀色。一个 agent 显示感叹号，多个显示数字。

working 只有一个 agent 在工作时，显示的是实时计时而不是标签——正在想的和卡住的，不该长得一样。

这四个颜色不会变

它们由含义固定，不跟你在"外观"里选的主题色走。要是跟着主题色走， 一个把强调色调成琥珀的人，会看到"工作中"和"需要你"变成同一个颜色。

状态屏幕上颜色含义
working 工作中 + 实时计时 青 正在干活
blocked / attention 需要你 + 实时计时 琥珀 在等人——放行、提问、权限确认
done 已完成 绿 这一轮干完了，你还没看
idle 空闲 暗白 永远不会点亮灵动岛——只在首页留一行安静的记录

控制面

每个按钮实际发出去的是什么

往 agent 那个 pane 里打原始按键。整套机制就这么多——没有 API 调用， 没有 agent SDK，也没有什么聊天通道。

按钮往 pane 里发的字节什么状态下出现出现在哪
Allow 0x0d——一个裸 Enter 需要你 Live Activity + 通知
Deny 0x1b——Esc 需要你 Live Activity + 通知
yes / continue 这个词，然后 Enter 需要你 只在 Live Activity
Reply 你输的文字，然后 Enter 需要你 · 已完成 只在通知
Stop 0x03——Ctrl-C 卡片上是工作中；通知里挂在每条"需要你"上 Live Activity + 通知

Allow 和 Deny 是照着 Claude Code 的权限确认框调的：肯定项默认高亮，Esc 取消—— 这也对得上绝大多数终端里的 yes/no 菜单。但话得说明白：这是盲打。 Offhook 不会去读那个提示框、确认现在高亮的到底是哪一项。yes 和 continue 是打进 pane 里的，不是发进某个聊天框。Reply 留空也照样发一个 Enter 出去。

两道保险，因为"悄悄失败"是最坏的结果

  • Prompt already gone。如果 Offhook 知道那个 pane 已经离开了"需要你"， Allow / Deny 不会发出去，而是弹一条通知告诉你。去回答一个已经不存在的提示， 有可能放行的是后面那个更危险的。如果 App 重启过、根本没有记录，这一下会照常发出去—— "没记录"永远不当拦截理由。
  • Not delivered。链路死了的话，Offhook 会强制唤醒并重试；实在够不着那个 pane 就直说： "Your tap didn't reach the agent — open Offhook and answer there." 锁屏上按了 Allow 却悄悄失败，是唯一值得再打扰你一次的情况——否则你会以为自己已经放行了， 然后就走开了。

herdr 上还有一步你看不见。tmux 能用 send-keys -t 直接寻址到某个 pane； herdr 不行——它只往当前 focus 的那个 pane 打字。所以 Offhook 会先把目标 pane focus 过去、 等帧通道真的切完，然后才写。5 秒内拿不到 focus 就报失败，而不是赌一把。 这一步的由来是评审时发现的问题：同时跑两个 agent 时，锁屏上的 Allow 有可能落进另一个 agent 的 pane。

提醒

通知本身，以及怎么调

全部是本地通知——在设备上从活着的会话里生成，没有任何服务器参与。 iOS 的通知权限是在你第一次带着 Notifications 开关连上主机时才问，不是一启动就问。

会发哪几种

  • 需要你。标题是 agent 名（claude）；正文是"它在问什么 + 在哪"， 如果没抓到 title 就退回通用的那句 「Agent 需要你的输入 — host · session · window」。每个 pane 只有一条， 新的会替换旧的，不会越堆越多。动作：Allow、Deny、Reply、Stop。
  • 已完成。✓ claude finished，正文是位置，带一个 Reply 动作， 让你不开 App 就能把下一条指令扔过去。这一条只有 hook 路径才会发—— tmux 猜法认定的"完成"是安静 4 秒，这个理由不足以震你一下口袋。
  • 会自动撤回。一个 pane 离开"需要你"之后，已经推送出去的那条会从锁屏上撤掉。 一条过期的"需要你"，等于在诱导你去回答一个已经没了的提示。
  • 你已经在看时会安静。如果你正好停在那个 pane 上，通知只进通知列表， 不横幅、不响。在任何别的界面上，它照常横幅。

设置 → NOTIFICATIONS

四个开关，默认全开。

开关App 里的说明关掉之后
Notifications Alert when an agent needs you 一条提醒都不发——Live Activity 照常
Live Activity Show agent session status in the Dynamic Island 锁屏卡片和胶囊都没有了——通知照常
Alert sound Play a sound when the agent needs you "需要你"和"已完成"两种提醒都静音
Show detail on lock screen Display what the agent is running/asking — off keeps it private "在干什么"这一行从卡片、小组件、通知正文里一起消失。状态还在。

同一组里还有两行：How notifications work（内容和这一页说的是一回事）， 以及只在 tmux 连接下出现的 Install agent hooks。如果你把 Notifications 和 Live Activity 两个都关掉，Offhook 会完全不再跟踪这个连接——什么都不看，什么都不轮询。

Agent Status 小组件

它和 Live Activity 是两回事，行为也不一样，值得单独说一句。可以加成桌面上的 小尺寸 / 中尺寸小组件，也可以加成锁屏挂件（矩形、圆形、行内）。它收不到任何推送： 读的是 App 每次同步时写下的一份快照，刷新时机由 iOS 自己决定。小尺寸和中尺寸优先显示 detail 而不是位置， 因为 Bash: npm install 比 work · 2:rednote 信息量大。中尺寸显示 3 个 agent。 快照超过 3 分钟没更新，所有状态点会统一变灰，摘要行变成 paused — open Offhook。

哪些情况下它不管用

Offhook 没有推送服务器。下面绝大部分都是这一个决定的下游后果， 在 App 这一侧修不掉。

后台

被挂起就等于冻住

iOS 一挂起 Offhook，那个 2 秒的扫描就停了。真机上验过：App 切后台后， 把一个 agent 从 blocked 改成 working，灵动岛纹丝不动；回到前台、跑完一次轮询，它才翻。

诚实

它宁可承认，也不装作还在动

Live Activity 带一个 120 秒的过期线。过线之后 iOS 把这张卡片标记为陈旧， 它显示的是 paused — open Offhook to refresh，而不是一个假的"working"一直挂着。

专注模式

它穿不过专注模式

"需要你"那条申请了 time-sensitive，但 Offhook 并没有带 time-sensitive 权限。iOS 会按普通提醒投递，所以勿扰模式照样把它压下去。

一次一个

只有最急的那个带按钮

Live Activity 最多带 4 个 agent；灵动岛展开态是头条加两行，再往后就是 +N more。只有第一个有按钮，胶囊里也只塞得下一个，其余的要靠 Switch 翻。

按键

Allow 并不会去读屏幕

就是 Enter 和 Esc，盲发。如果你用的某个 TUI 把危险选项放在默认高亮上，Allow 按下去就是它。 那道"提示已消失"的保险，只在 Offhook 确切知道提示没了的时候才拦。

Mosh

Mosh + tmux 没有 agent 状态

Mosh 承载不了 tmux 控制模式，也承载不了 herdr 的帧协议，所以在 Mosh 上这两个跑的是各自的 TUI。 Mosh + tmux 的连接下，灵动岛和它的通知完全不被驱动。Mosh + herdr 是可以的—— 控制面走一条轻量的 SSH 边车。

纯 SSH

没有 multiplexer 就没有 agent 状态

Multiplexer 选 None 的连接，根本没有地方可以读状态。agent 状态要么靠 tmux，要么靠 herdr—— 这也正是那个选择器存在的理由。

herdr

最多滞后 8 秒

herdr 的 CLI 没有手机够得着的事件订阅，所以 Offhook 只能轮询：有变化时 2 秒， 树安静下来退到 8 秒。你在笔记本上做的改动，最多会晚这么久才出现。在 App 里的操作是立刻刷新的。

herdr

直连是独占的

一个 pane 同时只能被一个客户端占着。两台 Offhook 连同一个 pane 会互相抢， 各自大约 2 秒夺回一次。这是 herdr 独占式直连的固有行为，客户端消不掉—— 它会退避，并且明确告诉你正在发生这件事。

还有几条小的，一并说完。herdr 0.7.3—— 也就是现在 Homebrew 上的稳定版——不上报 pane 的命令名和 agent 名，所以面包屑会退回 pane N，空闲的 agent 在那儿也永远不会长出一行。herdr 只看得见自己的 pane： 你在主机的普通终端里起的 agent，它是看不到的。App 重启之后，Offhook 没有"状态是什么时候开始的" 这份记录，所以那些行宁可不显示时长，也不编一个出来。还有，按钮上的字本身——Allow、 Deny、Reply、Stop，以及 Not delivered、 Prompt already gone 这两条失败提醒——目前不分语言，一律显示英文。

常见问题

大家最先问的几个

我的服务器上要装东西吗？

herdr 上不用——agent 状态本来就是协议字段。tmux 上，如果你想要准确的状态和"它在问什么"那一行， 就要装：设置 → Install agent hooks 会把完整命令摆给你看，先备份你的配置， 并且只在你按下 Run 时才执行。不装的话，Offhook 退回去盯输出和终端响铃——那是猜， 而且它就是这么说的。

Offhook 关掉之后，它能把我叫醒吗？

不能。所有提醒都来自正在运行的 App 去读活着的会话，而 iOS 会把它挂起。 状态会一直停在那儿，直到你回来。没有推送服务器可以解决这件事—— 这和"没有账号、中间没有任何东西"是同一个原因。

能不能不让 agent 问的内容显示在锁屏上？

把 Show detail on lock screen 关掉。Bash: npm install … 这一行会从 Live Activity、小组件和通知正文里一起消失。你仍然看得到是哪个 agent、在哪， 以及它是不是在等你。

我按了 Allow，但那个提示早就过去了会怎样？

如果 Offhook 知道那个 pane 已经离开"需要你"，它什么都不发，并告诉你提示已经没了。 如果 App 重启过、没有记录，这个 Enter 会照常发出去——这也正是为什么提示一解除， 那条通知就会从锁屏上被撤掉。

灵动岛能同时显示我所有的 agent 吗？

胶囊里一次只有一个——iOS 在那儿只渲染一个 Live Activity。展开态是头条加两行再加一个计数， Switch 按钮用来轮换胶囊显示哪一个。要看全的话，首页的 Agents 区块才是完整列表。
