文档

建立一个连接

从点 ＋ 到拿到一个能敲命令的 shell，中间发生的全部事情：表单里每个字段、 密钥从哪来、指纹提示怎么读、multiplexer 怎么选，以及主机上没装 tmux / herdr / mosh-server 时 Offhook 会怎么做。主机现成的话，一分钟左右。

加主机

「名称」「主机」「端口」「用户名」。只要「名称」和「主机」都有内容，「保存」 就能点了，其余都有能用的默认值。

选认证方式

密码、在手机上生成的密钥，或者粘一段 PEM。密钥本身进 iOS Keychain， 连接记录里只留一个指向它的引用。

核对指纹

第一次握手会停下来，把主机公钥指纹和用来比对的 ssh-keygen 命令一起摆给你。信任，或者取消。

先说一件小事：界面是中英混排的

绝大多数标签有中文，但 herdr 相关的几处 （Multiplexer、None、Custom herdr Path、 Install herdr）以及 Copy Public Key 等几个还没翻译， 中文系统下仍然显示英文。另外，凡是文案里要按 multiplexer 换词的地方 （空态、「创建会话 / 创建 Workspace」按钮、附加中的提示），目前一律走英文—— 换词是靠拼接实现的，拼出来的句子还没进翻译表。下面按你在屏幕上实际看到的样子写。

第一步

加主机

首页顶部有两个圆按钮：齿轮进设置，＋ 新建连接。＋ 打开「添加连接」； 同一个表单也是编辑器——长按卡片选「编辑」，它以「编辑连接」的标题打开。

连接

四个字段，两个必填

「名称」是卡片上显示的名字，「主机」填域名或 IP，「端口」默认 22—— SSH 和 mosh 的引导都走这一个端口，表单里没有第二个端口字段。

  • 「名称」和「主机」都非空，「保存」就可用
  • 「用户名」不做校验，留空也能存下来，所以别忘了填
  • 「漫游 · MOSH」和「高级」两组全是可选的

这些东西存在哪

连接的元数据——名称、主机、端口、用户名、你选的 multiplexer——是 UserDefaults 里的一段 JSON。密码和私钥不在里面：它们进 iOS Keychain，存成一条 generic password，连接记录里只留一个形如 offhook.secret.<uuid> 的不透明引用。

Keychain 条目用的是 kSecAttrAccessibleWhenUnlockedThisDeviceOnly：只在手机解锁时可读， 并且不进备份、不随设备迁移。这是刻意的，代价见下面 换手机要从头来。

删掉一个连接

长按卡片能看到「打开」或「连接」、「编辑」、「断开连接」（在线时） 和「删除连接」。确认框把话说明白了：从本设备移除已保存的服务器及其存储的凭据。 如果这个连接用的是「SSH 密钥」页里的密钥，那把密钥不会被删——只有属于这个连接自己的 凭据会被清掉。

删除不会做的事：它不会忘掉你信任过的主机指纹。那条记录仍留在 Keychain 里，以「主机 + 端口」为键。

连内网主机

第一次访问局域网地址时，iOS 会弹本地网络权限。拒绝之后公网主机照常能连， 192.168.1.10 这类连不上。弹窗里的说明就是 App 里写的那句： Offhook connects to servers on your local network over SSH and mosh (UDP). Without this permission, connections to LAN hosts (e.g. 192.168.x.x) will fail.

第二步

选认证方式

「认证」这一组是个二选一的分段控件：「密码」或「SSH 密钥」。 没有第三种——不支持 keyboard-interactive，不支持证书，不支持 agent forwarding。

密码

一个密文输入框。点「保存」时写进 Keychain，之后每次连接都在开 socket 之前读回来。

SSH 密钥：两条路

切到「SSH 密钥」会出现一行「密钥」，菜单里列出「SSH 密钥」页面里的每一把， 形如 名字 · 算法；菜单最下面还有一个出口：「改为粘贴 PEM…」。 选托管密钥，连接会记住是哪一把；选那个出口，则出现一个「私钥（PEM）」编辑框让你粘。

能用来认证的密钥类型：ED25519、RSA、ECDSA P-256， 以及 Secure Enclave 的 P-256——后者的签名在芯片里完成，私钥从不进内存。

用不了的东西

  • 带口令加密的私钥。解析私钥时 Offhook 从不传解密口令，所以加密过的 PEM 直接失败。先对副本去掉口令——ssh-keygen -p -N "" -f ./key-copy—— 原文件留着别动。
  • ECDSA P-384 / P-521。会被拒，报不支持的 SSH 密钥类型。 P-256 没问题。
  • 硬件 token。「添加密钥」里有「硬件」这一页，但它只是说明页： 确认按钮永远不会亮；连接的密钥菜单也把 ECDSA-sk 过滤掉了， 因为私钥那半在 YubiKey 上。
  • ProxyJump / 跳板机、agent forwarding、登录后自动执行的命令。 表单里没有，代码里也没实现。跳板要在网络层解决，比如 VPN 或 Tailscale。

关于 Face ID，把话说准

这里最容易被理解成比实际更强，所以说清楚：在连接表单里输入的密码、 以及在连接表单里粘贴的 PEM，都没有生物识别门禁。它们仍然只存在本机、只在解锁时可读， 但读取时不弹 Face ID。

只有在「SSH 密钥」页面里创建、并且打开了「需要 Face ID」（默认是开的） 的密钥，才会以 .userPresence 保存——每一次读取都要 Face ID、 Touch ID 或设备密码。在意这一层的话，就在那边建密钥，然后让连接指向它。

有两个连带后果值得知道。凭据是在开 socket 之前读的， 所以带 Face ID 的密钥是先弹 Face ID、再弹主机指纹提示。另外，解密后的明文只在前台缓存： App 每次进后台都会清空它——否则「每次读取都验证」会悄悄退化成「每次启动验证一次」。 所以从后台回来触发重连时，会再问你一次。

第二步 · 补

生成或导入密钥

设置 →「键盘 · 密钥」→「SSH 密钥」。里面两组：「本机 · SECURE ENCLAVE」 放硬件托管的，「已导入」放你带进来的。＋ 打开「添加密钥」，三个页签。

生成

「名称」、算法（ED25519 带 REC 标记 / ECDSA-sk / RSA-4096）、可选的「备注」。「保护」组里是「需要 Face ID」和 「存入 Secure Enclave」。打开 Secure Enclave 会把算法强制成 ECDSA P-256—— 芯片只签这一条曲线，算法控件会跟着变。

默认也推荐 ED25519。这里选 ECDSA-sk 会故意失败： 那种密钥由 token 生成，不由手机生成。

导入

「名称」、「备注」、一个等着 -----BEGIN OPENSSH PRIVATE KEY----- 的 PEM 编辑框， 以及只用来算指纹的「公钥行（可选）」。

把公钥送上服务器

长按密钥那一行：Copy Public Key、 Copy Fingerprint、Share Public Key、「删除密钥」。 这个长按菜单是公钥离开 App 的唯一出口，所以它是最容易被漏掉的一步。 把这行粘进服务器的 ~/.ssh/authorized_keys：

# 在主机上执行，剪贴板里是 Copy Public Key 复制出来的那一行
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAAC3Nza… phone' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

App 里显示的指纹和 OpenSSH 打印的是同一种形态——SHA256: 加上公钥 blob 的 SHA-256 的无填充 base64——所以可以和 ssh-keygen -lf -E sha256 the-key.pub 的输出逐字符比对。

关于这个页面，四句实话

  • 「口令」那两个框不加密任何东西。「口令」和「确认口令」只驱动强度条和 一致性校验，之后既不会传给密钥生成器，也不会传给 Keychain；生成的 ED25519 密钥是以 cipher none 写入的。真正保护它的是 Keychain 加上（你开了的话）Face ID， 不是那个输入框。别把 Offhook 生成的密钥当成「有口令保护的密钥」。
  • 「绑定主机」目前只是展示。芯片会被保存、会被画出来，但选密钥时没有任何代码 去读它。要指定用哪把，就在连接里选。（这一组的说明里提到的「SSH 密钥详情页」同样 还不存在，每行只有长按菜单。）
  • 导入的 ECDSA 密钥会被标成 ECDSA-sk，而连接的密钥菜单把 ECDSA-sk 过滤掉了——所以导入的 P-256 密钥不会出现在那个菜单里。 把这段 PEM 直接粘进连接表单，那条路径支持 P-256。
  • Secure Enclave 里的密钥导不出来，这是设计如此。建的时候就把公钥复制走， 私钥没有第二次机会。

第三步

核对主机指纹

Offhook 走的是 TOFU（首次使用即信任），和 OpenSSH 的 known_hosts 同一套 模型。对某个「主机 + 端口」的第一次握手会停下来问你，没有任何自动信任的路径。

第一次连

新主机

首次连接 db-01.example.com:22。

密钥指纹：
SHA256:8kQ2n…

请核对其与服务器一致（如 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`）。

                          [ 取消 ]   [ 信任 ]

去主机上跑那条命令——串口控制台、已有的会话、云厂商的网页终端都行， 只要不是你正在验证的这条连接——然后比对。Offhook 只负责把指纹摆给你看， 它没办法替你判断对不对。

指纹变了的时候

⚠️ 主机密钥已变更

db-01.example.com:22 的密钥与本设备存储的不一致。
这可能意味着服务器被重装——也可能是连接正被拦截。

已存储：SHA256:8kQ2n…
新密钥：SHA256:pR7wY…

              [ 断开连接 ]   [ 信任新密钥 ]

注意两个按钮的分工。「断开连接」是 cancel 角色——弹窗把它当安全选项， 误触也落在它上面。「信任新密钥」是 destructive 样式，因为一旦接受就永久覆盖 已存的指纹。服务器重装和中间人攻击弹出的是一模一样的框，只有你能分辨。

信任是怎么存的

  • 指纹存在 Keychain，不是 UserDefaults。 如果放在能被备份还原的 plist 里，只要预置一条指纹，就能让一把被劫持的密钥判定为 「已信任」并静默连上去；所以这份映射放在备份写不进去的地方。
  • 记录以主机 + 端口为键。同一台机器的 22 和 2222 是两条记录，会问两次。
  • 指纹是对完整 SSH 线格式编码（含 ssh-… 头）算的， 这也是它能和 OpenSSH 的输出对上的原因。
  • 如果界面上没有东西能回答这个提示，握手会直接失败。两个处理器都默认拒绝， 没有「没人应答就当作信任」这条分支。

局限：没有 known-hosts 管理界面

Offhook 没法列出你信任过哪些主机，事后也看不到它们的指纹， 更没有「忘记这台主机」。删掉连接不会带走它的指纹。服务器正常换了密钥（重装、迁移）之后， App 内唯一的路径就是在那个警告框里读完两个指纹、然后接受变更。

而且因为信任只存在本机、不进备份，换新手机等于从零开始： 每台主机第一次连都会再问一遍。这和「还原的备份不会带进一条被人预置的指纹」是同一个性质， 是取舍不是疏漏——但配第二台设备之前值得先知道。

第四步

选 multiplexer

「高级」组里的 Multiplexer 行有三个选项，菜单里各带一句 说明：None — Single shell, no session persistence； tmux — Mature, already on nearly every host； herdr — Built for coding agents — agent status needs no hooks。 （这几句目前还是英文。）

tmux

你机器上多半已经有了

  • 走 control mode，session / window / pane 都是原生渲染
  • 附加到已经在跑的东西上，不改它的样式
  • agent 状态需要在主机上装一行 hook
  • 路径字段：「自定义 tmux 路径」

herdr

为 coding agent 而写

  • agent 状态是协议字段——主机上不用装任何东西
  • workspace 与 tab，一个占满屏宽的 pane
  • 隔离任务：一个 git worktree、一个 workspace、一个 agent，一张表单搞定
  • 路径字段：Custom herdr Path

选 None 就是一个纯 shell：断线即失去会话， 也没有什么「缺失」需要 Offhook 汇报。在这个选择器出现之前保存的连接没有 multiplexer 这个字段，会回落到老的 useTmux 开关——而老表单一直把它写成 true， 所以它们解码出来就是 tmux，和一直以来的行为一致。

这两个不能互相顶替

tmux 和 herdr 是两个独立的 server，各自持有互不相干的会话。 你选了一个而主机上只有另一个，Offhook 会告诉你，然后退成一个纯 shell。 它不会去附加另一个——那等于把别人的工作端到你面前，还说这是你的。 这条规则在表单说明、降级逻辑和设计文档里是同一句话。

自定义路径一旦填了，就没有安全网

路径字段跟着你选的 multiplexer 走，而填了它就等于你为这个二进制背书： 路径非空会整个跳过能力探测。填错了就没有 banner、没有优雅降级， 你会直接吃到远端 shell 的原始 command not found。

表单默认把这些字段留空，正是因为这个。早期版本给 mosh-server 预填了 Apple Silicon 的 Homebrew 路径，结果每台 Linux 主机都绕过了 mosh 的降级、 直接死在一句原始报错上。除非二进制确实不在 PATH、也不在探测额外加的那五个目录里， 否则别填。

走 mosh 时，两者都跑自己的 TUI

mosh 的协议承载不了 tmux 的 control mode，也承载不了 herdr 的帧协议。 打开「使用 Mosh」并且选了 multiplexer，你仍然会得到 tmux 或 herdr—— 但是以它们自己的全屏文本界面跑在 mosh 的 shell 里，用它们自己的 prefix 键。 丢掉的是原生 pane 渲染：终端里显示的就是那个 multiplexer 自己的画面， 连侧边栏一起。表单在「高级」的说明里也是这么写的。

但面板不会丢。走 mosh 时 Offhook 会另开一条轻量的 SSH 连接 专门跑控制面——tmux 走 -CC sidecar，herdr 走 herdr api snapshot 轮询——所以 Sessions / Workspaces 面板、 Windows / Tabs 面板、首页的树和面包屑照常可用。这条连接拨的是 mosh 引导时 已经认证过的同一台主机，信任已经缓存，不会再弹一次指纹。万一哪天不再成立， 这条 sidecar 是默认拒绝的：你会丢掉面包屑，而不是被静默地信任一把新密钥。

prefix 键相同，键位不同

herdr 的默认 prefix 也是 ⌃B，但后面接的键是它自己的一套， 其中一个会让你付出代价：⌃B q 在 tmux 里是显示窗格编号，在 herdr 里是 detach。herdr 切 workspace 用 ⌃B w，切 tab 用 ⌃B n / ⌃B p；tmux 那边对应的是 ⌃B s 和 ⌃B 1-9。Offhook 各个面板底部印的就是当前连接该用的那一组， 照着那里按，别照着 tmux 的肌肉记忆按。

herdr 的三条边界，先说在前面

  • 直连是按 pane 独占的，而 Offhook 带 --takeover 附加—— 必须带，否则重连会撞上自己上一条没断干净的附加。因此两个 Offhook 客户端连同一个 pane 会互相把对方踢下去，这个 pane 同一时刻只能归一个。Offhook 会数自己 「不是主动断的」那些断开：30 秒内被踢三次，就退避 30 秒并直说 Another client is using this pane — retrying shortly， 而不是每两秒抢一轮、你打的字却落在一条刚被踢掉的通道上。对方一走，它自己就恢复。 独占是 herdr 的机制，客户端消不掉。桌面上的 herdr TUI 不占用 attach owner， 所以「笔记本开 TUI + 手机连同一台」理论上安全——但这个组合我们还没在真机上验过， 所以不写成结论。
  • herdr 0.7.3（截至 2026-08-07 的 Homebrew stable，协议 16）不上报 pane 的命令， 所以面包屑会退回成 pane 1、pane 2。更新的版本有这个字段。
  • herdr 只认得跑在它自己窗格里的 agent。它的 agent 状态之所以不用装东西， 是因为那些窗格本来就跑在 herdr 这个 runtime 里——它不是进程扫描器。 你在普通 SSH shell 里、或者在同一台机器的 tmux 里起的 Claude Code， 不会出现在 Agents 列表里，也不会点亮灵动岛。想让它被跟踪， 就在 herdr 的窗格里起（或者用 New Agent Task 起）。

第五步

主机上缺东西时

依赖缺失绝不会阻断连接。Offhook 在第一条 SSH 通道上探测一次， 降级到一个能用的形态，然后告诉你它放弃了什么。

探测看的是哪些地方

ssh host command 起的是非登录、非交互的 shell， 不会 source .zprofile 或 .bash_profile—— 所以一个装得好好的 Homebrew tmux 本来会被探成「没装」。 因此探测在 PATH 之外还会看这五个目录：

/opt/homebrew/bin  /opt/homebrew/sbin  /usr/local/bin  /usr/local/sbin  $HOME/.local/bin

$HOME/.local/bin 是专门为 herdr 加的： 它的安装脚本把二进制放在那里，并且刻意不动任何 rc 文件。装在别处的工具会被读成「没装」 ——这是探测的盲区，而自定义路径字段就是给这种情况准备的。

降级矩阵

你选的主机上没有实际发生什么
SSH + tmuxtmux 退成单个纯 SSH pane，顶部一条 banner
SSH + herdrherdr 退成纯 shell，顶部一条 banner——绝不会改用 tmux
Moshmosh-server 复用已经认证过的那条 SSH 会话，加一条 banner； 首页卡片的 MOSH pill 变灰并带 ⚠
Mosh + multiplexer那个 multiplexer 裸 mosh shell——不发 attach 命令，后台也不会有 sidecar 反复重试
None— 没什么可缺的，也就没有 banner

降级只影响当次会话。中间你把东西装上了，下次连接重新探测，能力自动回满。

banner 和「在主机上安装」面板

降级的会话在终端顶部显示一条可关闭的 banner—— 此主机未安装 tmux —— 已使用纯 SSH 会话。、 herdr not found on this host — plain shell session.（这句还是英文）、 或未找到 mosh-server —— 已改用 SSH 连接。——右侧带一个「安装 …」按钮。 banner 后面的终端完全可用。

面板标题是「在主机上安装」，开头就是它守住的那句承诺： Offhook 绝不会静默安装任何内容。请在你的 shell 中运行下面的命令 —— sudo 及其输出全程可见。接着是按探测到的包管理器生成的命令：

apt-get   sudo apt-get install -y tmux mosh
dnf / yum sudo dnf install -y tmux mosh
pacman    sudo pacman -S --noconfirm tmux mosh
apk       sudo apk add tmux mosh
brew      brew install tmux mosh

herdr 不在任何发行版仓库里，所以它走自己的安装器：
brew      brew install herdr
其他      curl -fsSL https://herdr.dev/install.sh | sh

tmux 和 mosh 放在同一条命令里，一趟就能把一台什么都没有的机器补齐。 要装哪些包是按这个连接自己选的 multiplexer 推出来的，而不是按「现在缺什么」： 选 tmux 的连接拿到 tmux mosh，选 herdr 或 None 的连接 如果只缺 mosh-server，拿到的就只有 mosh——用 herdr 的人不会被塞一条装 tmux 的命令。没探到包管理器时，面板会直说 Couldn't detect a package manager.，并给一段通用指引， 而不是给你一条注定失败的命令。herdr 是例外：它的安装脚本根本不需要包管理器， 所以永远有东西可以给。

三个按钮：「在终端运行」把命令粘进当前 shell 并回车， sudo 提示和每一行输出都留在屏幕上；「复制命令」；「重新检测」重跑探测。 重新检测的结果是已安装 —— 重新连接以启用。加一个「重新连接」按钮， 或者仍未检测到。请运行命令并等待其完成，然后重新检测。

如果 herdr 不是用 Homebrew 装的，面板还会补一句： Installs to ~/.local/bin. Offhook looks there when probing and launching, so you don't need to change PATH.

重新检测在哪里不管用

走 mosh 时已经没有 SSH 通道可探了——mosh-server 接管之后， 引导用的那条通道就关了。这时「重新检测」会说 当前传输方式无法重新检测 — 请重新连接以生效。并给出「重新连接」， 而重连本来也就是真正的解法。

还有一处刻意保留的粗糙：探测结果按连接缓存， 所以一台上次被判定为缺 tmux 的主机，下次连接时可能先闪一下 banner， 等新的探测回来才消失。反过来的错误（缓存说「都在」其实没有）后果更糟， 所以缓存宁可错在这一边。

空终端的两种含义

转圈（Attaching tmux… / Attaching herdr…）大约四秒后， 终端会落到两种状态之一，含义完全不同。一种是这台主机没装那个 multiplexer， 配一个 Install … 按钮；另一种是二进制在、只是没有东西在跑： This server has no running sessions. Offhook only attaches — create the first one to start.，按钮是 Create Session。二进制缺失和无会话是两件事， 别当成同一个问题处理。

这几句话会跟着 multiplexer 换词，因为 herdr 没有「会话」这个概念： herdr 连接上同一屏读作 No herdr workspaces / This server has no running workspaces.，按钮是 Create Workspace。 整个 App 都是这个规矩——tmux 是 session / window / pane，herdr 是 workspace / tab / pane，删掉一个的动词也从 Kill 换成 Close。 上面这几句目前在中文系统下也是英文（见开头那条「中英混排」）。

规矩

Offhook 绝不会做的三件事

整条初始化路径都是围着这三条搭的。它们写在源码里、写在表单自己的 说明文字里、也写在设计文档里，不只是写在这一页。

安装

绝不静默安装

每条安装命令都先给你看，再在你可见的 shell 里执行，sudo 交互和输出一样不少。 Offhook 只负责代填命令，按钮由你来按。

会话

绝不擅自创建或改造会话

它附加到已经在跑的东西上，不动你的配置。只有你点「创建会话」才会有新会话； 而且只有通过 Offhook 创建的会话才会套上它的原生外观——隐藏状态栏， 断开时还原。

复用器

绝不替你换 multiplexer

你选了 herdr 而主机上只有 tmux，你会拿到一个纯 shell 加一条 banner—— 而不是别人的 tmux 会话被包装成你的。

连不上的时候

把报错读懂

连接失败会弹一个标题为「连接错误」的提示。这些文案是从底层库的原始错误 重写过的，目的就是让它说一句你能照着做的话。

你看到的该查什么
无法连接到服务器。请检查主机、端口，以及服务器是否在线。 DNS、防火墙、端口。地址是内网的话，还要看是不是拒绝了 本地网络权限。
认证失败——服务器拒绝了你的用户名和密码 / 密钥。 用户名；以及公钥是不是真的写进了那个用户的 authorized_keys。
服务器拒绝了这种登录方式。 主机把这种方式关了，比如 PasswordAuthentication no。改用密钥。
不支持的 SSH 密钥类型：… ECDSA P-384 / P-521，或者一段解析不了的 PEM。换 ED25519。
Couldn't read the saved credential.（这句还是英文） Keychain 里那条没了——通常发生在重装或重签名之后。 进「编辑连接」重新输密码或重选密钥。
已连接，但服务器拒绝打开会话通道。 认证过了；是服务端账号受限或通道用尽。
App 切到后台时，还会盯着我的 agent 吗？

不会。iOS 会挂起 App、挂起保活定时器、挂起轮询，agent 状态会停在那里， 直到你回到 App——灵动岛和 agent 列表会在你回来之后的第一次轮询补上。 没有推送服务器，因为根本就没有 Offhook 服务器。这是「中间不放任何东西」的代价， 我们照实说。

为什么又问了一次 Face ID？

解密后的凭据只在前台缓存，每次进后台都会被清掉。否则一把配置成「每次读取都验证」 的密钥，会悄悄退化成「每次启动验证一次」。从后台回来触发重连时要重新从 Keychain 读， 所以会再问。

断线了要我做什么吗？

一般不用。SSH 会话在 App 前台时每 12 秒探一次链路，断了会自己重连； tmux 重新附加会把你送回原来那个 pane，服务端的回滚缓冲也还在。herdr 会重新附到 当前聚焦的窗格上，但它的帧协议传的是整屏重绘而不是字节流，本地攒不出回滚缓冲—— 历史是你往上滚时由服务端翻页给你的。Mosh 完全不走这条探测： 它自己在 UDP 上处理恢复和漫游。如果 App 在后台待了超过 20 秒， 回来时会跳过探测直接重连——因为 iOS 那时几乎必然已经把 socket 杀掉了。

同一把密钥能给多台主机用吗？

能，在每个连接的「密钥」行里选同一把就行。删掉其中一个连接不会删掉密钥， 因为凭据属于密钥、不属于连接。密钥自己那边的「绑定主机」芯片目前还没有任何代码 去读，暂时可以忽略。

我改了端口，为什么又问我主机密钥？

信任的指纹以主机和端口为键，host:22 与 host:2222 是两条独立记录。核对一下，再信任一次。
