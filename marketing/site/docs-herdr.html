Using herdr

herdr is a terminal multiplexer written for CLI coding agents. On a herdr connection Offhook knows what every agent is doing with nothing installed on the host. Setup, vocabulary, key bindings, the Agents section, isolated tasks — and at the end, everything that does not work.

herdr is a single Rust binary. Offhook supports it because it moves three jobs off the phone and onto the server — jobs the tmux path still does by hand.

Agent status

A protocol field

agent_status sits on every pane and rolls up pane → tab → workspace. On tmux, Offhook needs you to install hooks that stamp @offhook_* options.

Scroll

Routed server-side

terminal.scroll is a protocol action; herdr decides whether a swipe becomes a mouse report or scrollback. On tmux, Offhook inspects #{mouse_any_flag} and picks.

Resize

Scoped to one pane

An attached client's resize hits only its own pane's PTY. On tmux a phone attaching shrinks the window for every client — hence Offhook's window-pinning machinery.

It is an alternative to tmux, not a replacement. The two are separate servers holding unrelated sessions. You pick one per connection, and Offhook never substitutes the other — attaching tmux because herdr is missing would show you someone else's work and call it yours.

Versions. Designed against herdr main / v0.8.0, protocol 19; verified on real hardware against 0.7.3, protocol 16 — which is what brew install herdr installed at the time. Three protocol versions apart. The decoder degrades field by field rather than failing a whole read; where 0.7.3 costs you something, this page says so.

Setup

Install it, then pick it per connection

herdr is in no Linux distribution repository — its own packaging covers Windows only. There is no apt-get line to offer, and Offhook refuses to synthesize one that would fail with "unable to locate package".

Install herdr on the host

Homebrew if you have it, the official script otherwise. The script drops the binary in ~/.local/bin and touches no shell rc file.

Pick herdr on the connection

Add Connection → ADVANCED → Multiplexer → herdr. Per connection, not global: your hosts don't all have the same tools.

Connect

Missing on the host? A banner says so and offers Install Assist. You get a plain shell, never a silent switch to tmux.

# whichever fits the host Offhook probed
brew install herdr
curl -fsSL https://herdr.dev/install.sh | sh

Offhook probes and launches with the same extra PATH entries, $HOME/.local/bin among them — otherwise the command Install Assist just handed you produces "herdr: command not found" on the next connect. A Custom herdr Path is trusted verbatim and bypasses both.

The ADVANCED group's footer, verbatim: "tmux and herdr hold separate, unrelated sessions. If the host doesn't have the one you pick, Offhook says so and drops to a plain shell — it never quietly attaches the other. With Mosh, herdr runs its own terminal UI; native rendering needs SSH."

  • Binary missing — banner "herdr not found on this host — plain shell session.", action Install herdr. Install Assist opens with "Offhook never installs anything silently. Run the command below in your shell — sudo and its output stay fully visible." Re-check flips to "installed — reconnect".
  • Server not running — empty state "No herdr workspaces" / "This server has no running workspaces. Offhook only attaches — create the first one to start." with a Create Workspace button that reads Creating… while it works.

That button is the only thing that starts a herdr server from Offhook (nohup herdr server, then workspace create --focus — a cold server comes up with zero workspaces, hence two steps). One wrinkle: on the Mosh path Offhook types a bare herdr, which does create a workspace when no server is running. Accepted, because that terminal is herdr's own UI and you see exactly what typing herdr would do.

SSH gets you more than Mosh here

Mosh transmits rendered screen diffs, which destroy line framing — the same reason tmux -CC cannot ride mosh. So herdr's frame protocol is SSH-only.

Agent status

Why status is free here and costs a hook install on tmux

On tmux, "which agent needs me" is inferred: you install hooks, they stamp pane options, and panes without hooks fall back to a guess from output and the terminal bell. On herdr it is a query — agent_status is already on every pane.

herdr agent_statusOffhook shows Where
working teal dot · "working" · live timer Home · breadcrumb · Island · lock screen
blocked amber dot · "needs you" Home · breadcrumb · Island · lock screen
done green dot · "done" Home · Island. Never rolls a window amber
idle no dot — a dim, quiet row Home only. Never lights the lock screen
unknown / absent nothing—
  • Those three colours are fixed, not your accent — pick an amber-ish accent and "working" and "needs you" would otherwise become the same colour.
  • Settings hides the Install agent hooks row on herdr connections, so a herdr-only user is never told to install tmux hooks.
  • tmux's output-and-bell heuristic is not layered on herdr. Guessing next to a reported truth is a strictly worse second opinion.
  • Verified on hardware with herdr pane report-agent --state blocked and --state working — herdr's own integration interface — with nothing installed on the host.
  • Optional and more authoritative: herdr integration install claude makes the agent report its own state instead of herdr reading the screen. Not required.

blocked → needs you Amber, with a count when more than one waits. The lock-screen card carries Allow, Deny and two quick replies.

working → teal timer A thinking agent and a stuck one stop looking alike. Working offers Stop, nothing else.

Answering from the lock screen

herdr needs the focus moved first

tmux addresses a pane directly with send-keys -t; herdr's frame channel types into whichever pane it is attached to. So Offhook focuses the target, waits for the retarget to finish, then writes — a keystroke sent mid-switch lands on a bare shell and dies. If focus can't be obtained, delivery fails loudly and the notification says "open the app" instead of pretending.

The alternative turned up in review: with two agents running, a lock-screen Allow could send someone else's Enter.

Vocabulary

Workspaces and tabs, not sessions and windows

One internal model drives both multiplexers, translated at the presentation layer. Reusing the model is not a reason to reuse tmux's words: reading "Kill Window" for something herdr calls a tab is a tax on every glance.

herdridtmuxOffhook says
workspacew1 session $0 Workspace / Workspaces
tabw1:t1 window @0 Tab / Tabs
panew1:p1 pane %0 Pane / Panes
  • The destroy verb follows the CLI: tmux Kill, herdr Close — because herdr's commands are workspace close / tab close / pane close.
  • The tree header reads WORKSPACES, and the Home stat chip counts both control planes — it used to be hardcoded TMUX and report 0 while a herdr workspace was live.
  • "Tab 1", not "1: 1" — herdr names a tab after its own number, and a tree of those is a wall of digits. tmux windows named after their command still read 2: logs.
  • "~ · w4" — herdr labels a workspace after its cwd, so four at ~ all read "~". Shared names get the raw id appended: the handle herdr's own CLI addresses by, not decoration.

Keyboard

⌃ b q detaches in herdr. That one is a trap.

Both default to Ctrl-b as the prefix, so Offhook's prefix handling and shortcut bar carry over unchanged. Three bindings do not, and one of them ends your session.

The Select Pane sheet used to print ⌃ b q on herdr connections. In tmux that lists panes. In herdr it detaches — the app was printing the key that drops your session. It now prints ⌃ b v, the split, because herdr has no "show me the panes" key at all and inventing one is worse than admitting it.

⌃ b s is unbound in herdr (workspaces are ⌃ b w), and ⌃ 1-9 jumps to a window by number in tmux while herdr steps with n / p.

Sheettmux printsherdr prints
Sessions / Workspaces⌃ b s ⌃ b w
Windows / Tabs⌃ 1-9 ⌃ b n/p
Panes⌃ b q ⌃ b v

The shortcut bar's "only inside a multiplexer" toggle counts herdr too. It used to be fed by "is there a tmux controller", always false on herdr — so a key you marked multiplexer-only vanished on the one connection you wanted it on.

Home

The Agents section answers the question you actually have

Host → session → window → pane answers "where is it", not "who is waiting for me". On herdr connections, Home puts an AGENTS section above the workspace tree, in the same card and the same scroll. No Agents tab, no separate page, no new navigation axis.

herdr connections only

A projection, not another poll

Every row comes from the snapshot the tree and the Dynamic Island already read. Zero extra remote calls.

  • Order: needs you → working → done → named idle last
  • Ties break by name then pane id, so it never reshuffles between polls
  • Tapping a row does what tapping a tree pane does — one way in
  • Header — AGENTS with a count chip, NEEDS YOU (or 2 NEED YOU) in amber, and a +.
  • Row — agent name, workspace · tab, state dot, elapsed time at the trailing edge. The dot carries a VoiceOver label, so colour is not the only channel.
  • Elapsed is minute-granular — now, 2m, 1h 12m. Never seconds: the poll behind it is up to 8 seconds coarse. It reads the same clock as the lock-screen timer, so the two never disagree.
  • A row needs a reason — a live signal, or an explicit idle stamp with an agent name on it. Anonymous quiet panes render nothing. Named idle rows are dim and dotless, sorted last: a claude at its prompt and "nothing running" are different answers.
  • Empty state — "Nothing running — start a task to isolate one". The header stays visible at zero agents, because hiding the section hid the + and made the first task impossible to create.

Isolated work

New Agent Task: a git worktree, a workspace, an agent

The + in the AGENTS header opens a four-field form. Filling it creates a real git worktree on the host and starts the agent inside it. Your working tree never moves.

The form

Repo, branch, agent, first message

TASK footer: "Creates a git worktree on the host, then starts the agent inside it. Your working tree is untouched." — FIRST MESSAGE footer: "Optional. Sent to the agent once it's running — leave blank to type it yourself."

Start becomes Starting… while it runs. Large checkouts take tens of seconds, and a button with no in-progress state reads as broken.

herdr worktree create --cwd '<repo>' --branch '<branch>' --label '<branch>' --focus --json
→ new worktree + new workspace + a pane already sitting in the checkout,
  at ~/.herdr/worktrees/<repo>/<branch>

herdr pane run '<root_pane>' '<agent>'   # types the command and presses return
herdr agent send '<root_pane>' '<prompt>'  # only if you typed one, 2s later

Not agent start: verified that it does not inherit the worktree's directory — the new pane lands in the CLI's own cwd. worktree create already yields a correctly located pane, so pane run is simpler and one fewer failure point. Every label is POSIX single-quoted before it reaches a shell.

Where the repo list comes from

herdr has no concept of "your repos", so Offhook looks — as two concurrent commands, on purpose. Pane cwds resolved with git -C <cwd> rev-parse --show-toplevel are small, fast and listed first; a $HOME scan (find -L "$HOME" -maxdepth 4, pruning Library, node_modules, media folders and hidden dirs, top 40 by mtime) races beside it on an 8-second client budget. Fused into one command it failed on a real device: an iCloud-backed $HOME stalled find past 25 seconds, the link went down, and the form offered nothing but "Other…".

Residual limit: once the budget expires the remote find keeps running to completion — an exec channel cannot be un-sent — so the prune list is its only real bound. The menu reads "Looking for repositories…" while scanning and "None found — no panes in repos, and nothing under ~" when empty; the last item is always Other….

  • Agents come from herdr server agent-manifests --json. The default prefers claude, then codex — alphabetical order once made the default agy on a real host.
  • Branch names are validated on the phone before any round trip (no spaces, no .., no trailing .lock, no ~ ^ : ? * [ \, and more). The reason appears under the field, so a disabled Start never looks broken.
  • herdr's own error text is shown verbatim — branch 'fix-scroll' already exists needs no translation.
  • Agent flags are not chosen for you. The manifest default runs; anything like --dangerously-skip-permissions you type yourself.

Removing a worktree takes two confirmations

Long-press a workspace row → Remove Worktree, shown only on workspaces that really are a linked worktree. The first command never carries --force:

1 · "Remove the worktree for <name>?" — "Deletes the branch checkout under ~/.herdr/worktrees. <repo> itself is untouched." Remove / Cancel.

2 · Only if herdr answers dirty_worktree_requires_force, which it does while leaving every file in place: "<name> has uncommitted changes" — "Those changes exist nowhere else. Removing the worktree throws them away." Delete anyway / Keep it. Only that tap adds --force.

This is herdr's own safety net, not something Offhook invented. Not verified on device: the long-press menu itself — idb cannot drive a SwiftUI context-menu long press, so menu → dialog → dialog is guaranteed by compilation and unit tests, with no device recording.

Limits

Everything that doesn't work, in one place

Most of these were found by running the thing on real hardware, and each one changes how you should use it.

Up to 8 seconds of staleness for changes made elsewhere. Offhook polls herdr api snapshot every 2 seconds while anything moves and eases to 8 once the tree stops changing. In-app actions refresh immediately; anything done on your laptop, by another client, or by an agent changing state waits for a poll. That ±8s error is why the Agents section never prints seconds.

No push. There is no Offhook server. Every alert is a local notification generated by the running app. herdr's socket does have an event subscription, but its CLI exposes no subscribe subcommand and a phone cannot open the host's Unix socket. Polling is the only mechanism available.

iOS suspends the connection in the background — agent state stops updating until you return. Verified on device: backgrounded, a pane flipping from blocked to working left the Island unchanged until one poll after returning. That is the necessary consequence of having no push server, and it is identical on tmux. The Live Activity carries a 120-second stale date, so the lock screen says "paused" rather than showing a frozen "working".

Direct attach is exclusive per pane — two clients on the same pane fight. Offhook must take over, because a reconnect always collides with its own stale channel, after which two direct clients re-claim about every 2 seconds. Not fixable from the client. Offhook does detect it: three unrequested closes in 30 seconds trigger a 30-second pause and a visible "Another client is using this pane — retrying shortly", clearing as soon as frames paint again.

Untested: your laptop running herdr's own TUI while your phone is attached. TUI clients don't occupy an attach slot, so in theory it is safe. It has not been tested, so it is not claimed.

One pane at a time. Native rendering shows a single pane, full phone width, by design — each additional pane would need its own SSH channel.

No full scrollback. herdr's read API offers only visible / recent / recent-unwrapped / detection, and its frames are absolutely-positioned cell repaints rather than an append-only stream, so they never accumulate into local scrollback either. History goes through server-side paging.

herdr 0.7.3 reports no pane title, agent name or label. A pane's command is empty, so the breadcrumb's third segment falls back to pane N — kept deliberately, since a vanished crumb takes the Select Pane sheet's only entry point with it. And with no agent name, idle rows never appear on 0.7.3.

No tmux-style layout string, so the pane board is inferred from the panes' reported geometry: same width means stacked, same height means side by side, otherwise a grid. The goal is every pane on screen and tappable with the real active one marked, not a pixel-accurate mirror.

herdr pane focus takes a direction, not a pane id — in both 0.7.3 and 0.8.0. The only id-addressable focus is herdr agent focus <pane_id>, which on a plain shell pane prints agent_not_found but still moves the focus: the server focuses first, then fails building the response. Offhook swallows that error on purpose. It is the dirtiest part of the integration and the code says so.

Named herdr sessions are not supported. herdr can run several independent servers via --session / HERDR_SESSION; Offhook only talks to the default socket. Worse, the app does not currently say this anywhere — split your host into named sessions and Offhook sees one of them with no hint about the rest.

Only herdr-hosted panes are visible. Observed for real: a claude running in Terminal.app, five herdr panes all idle, and the section correctly saying "Nothing running" while the user was certain something was running. herdr is a runtime, not a process scanner — start agents with New Agent Task or inside a herdr pane.

Bandwidth and frame rate have never been measured. Cell-positioned repaints over SSH versus tmux -CC's output stream under a heavy-output agent — the repaints may well cost more bytes. No performance claim is made in either direction.

Worktrees land in ~/.herdr/worktrees/<repo>/<branch>, not beside the repo, with no path override in this version. Large repositories take tens of seconds. git worktree add against a dirty repository should be fine, since it is an independent checkout, but that has not been verified.
