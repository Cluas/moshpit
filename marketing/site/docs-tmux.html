Using tmux

Offhook attaches as a tmux control client and draws your sessions, windows and panes as native iOS views. Here is what that does, what it changes on your server, and where it stops.

You need tmux on the host, on PATH — or a path in the connection form's Custom tmux Path field. Nothing else. The hook install below is optional and separate.

If tmux is missing the session degrades instead of failing: a plain SSH single pane plus a banner reading "tmux not found on this host — plain SSH session.", and an Install tmux action that shows the command for your package manager and runs it only when you tap it. Offhook never silently swaps in a different multiplexer — tmux and herdr hold unrelated sessions. A custom tmux path skips the check entirely, since the probe only walks PATH.

One line into your login shell

Offhook doesn't shrink tmux's own text UI onto a phone. It attaches as a control client — tmux -CC, the same control mode iTerm2 uses — and renders the result itself. On connect it writes exactly this:

tmux set -g history-limit 50000 2>/dev/null; tmux -CC attach

attach with no -t means your most recent existing session. Offhook never runs tmux new on its own. With no sessions on the server you get an empty state saying so, and a Create Session button you press yourself.

Discovery is three commands on the same channel, re-run whenever the tree changes. -a is every session on the server — that's why the home screen can show several expanded at once:

list-sessions -F '#{session_id} #{session_attached} #{session_name}'
list-windows -a -F '#{session_id} #{window_id} #{window_index} #{window_layout} …'
list-panes   -a -F '#{pane_id} #{window_id} #{pane_index} … #{pane_current_command}'
  • Attach has a 22-second deadline. If tmux never confirms, the home card reads stalled — "Attach didn't complete — tmux never confirmed." — with a retry. SSH itself is still alive; it's the tmux handshake that didn't land.
  • Control mode cannot run over mosh. Mosh sends screen diffs, not a line-framed protocol. On mosh + tmux, Offhook renders tmux's ordinary full-screen UI over mosh and opens a second, sidecar SSH connection running -CC just to feed the breadcrumb and the sheets. No SSH, no native sheets — you get a bare tmux attach.

Getting around

One pane, full screen, always

Offhook shows a single pane and zooms it for you (select-pane -Z, plus resize-pane -Z when the window has splits and isn't zoomed). Splits are never drawn side by side, and the zoom is left in place when you leave — your layout isn't Offhook's to curate, and prefix z restores it anywhere. The Select Pane sheet is the only view of the real split geometry.

The top bar is three tappable crumbs — session › window › pane — each opening its sheet. The pane crumb names the agent if a hook stamped one, else the foreground command, else pane 2.

SheetWhat it listsFooter
Sessions Every session on the server — 3 windows · 2:logs for the active one, attached / detached for the rest Swipe to switch · ⌃ b s
Windows The active session's windows as 2 panes · nvim, with an agent dot and its text label — colour alone isn't the signal Swipe to switch · ⌃ 1-9
Select Pane The real layout tree from tmux's layout string, drawn proportionally; each cell shows the window-local index and the pane's command Tap to focus · ＋ splits a new pane · ⌃ b q

Limit: the Windows sheet lists only the active session's windows. Other sessions live in the home tree. The footer key chips print what your tmux binds, for a hardware keyboard on the host — they're per-multiplexer because ⌃ b q lists panes in tmux and detaches in herdr.

Swipe

One finger, two axes

A single pan gesture handles both. The axis locks after about 12 pt of accumulated drag; a horizontal swipe commits at 40 pt with a haptic tick.

  • Left for next, right for previous — it wraps
  • More than one pane in this window? It cycles panes. Otherwise, the session's windows
  • Works on SSH + tmux and mosh + tmux (routed through the sidecar). It is not wired on herdr, whose sheets say "Tap to switch"

Creating and killing

Create from the + in a sheet header or the home screen's SESSIONS row; rename and kill are in the long-press menu on any row. Names are single-quoted, so a session called my project works.

ActionWhat Offhook sendsNotes
New session new-session -d -P -F '#{session_id}' Then selects it. A Create that leaves you where you were reads as "did nothing".
New window new-window -P -F '#{window_id}' Field is Name (optional) — "Leave blank to let the program name it."
New pane split-window, then resize-pane -Z The split is immediately zoomed back to one full-screen pane.
Rename rename-session / rename-window tmux panes have no name, so there's no Rename for a pane.
Kill kill-session / kill-window / kill-pane Confirmations spell out the damage: "Kill window 2: logs? Every pane in it dies."

Killing the last session exits the tmux server and closes the control channel, so Offhook prunes its own tree first rather than hang waiting for a reply that never comes. When tmux refuses — a duplicate name, say — you get tmux's own error text for three seconds. Nothing is swallowed.

Scrollback

Two different things called "scroll up"

A pane's history lives on the server; what the app holds locally is only what tmux repainted. So Offhook asks tmux which kind of scroll this is — display-message -p '#{mouse_any_flag}' for the active pane, refreshed on every switch and at the start of every drag. It asks rather than guesses, because under mouse on the rendered terminal can't tell.

The program grabbed the mouse — Claude Code, vim --mouse, less --mouse

Offhook synthesizes wheel events into the pane, so the program scrolls itself, tmux never enters copy-mode, and typing still works. Clamped to six per flick.

ESC [ < 64 ; col ; row M   # wheel up   (older)
ESC [ < 65 ; col ; row M   # wheel down (newer)

A plain shell

tmux copy-mode over the control channel, one step per 0.18 s. Any keystroke sends -X cancel first, so typing always drops you back at the live bottom — and scroll-down does nothing until you've scrolled up, because there's no copy-mode to scroll down in yet.

copy-mode -t %41
send-keys -t %41 -N 3 -X scroll-up

What you can actually scroll into

On attach, Offhook replays a pane's history once (capture-pane -e -S -2000 -E -1) — up to 2 000 lines, and only for primary-screen panes. A pane in the alternate screen (vim, top, Claude Code) gets its visible frame and nothing above it: a text dump has no cursor positioning and would corrupt a full-screen program.

So a Claude Code pane you just attached has no local history above the prompt. Scrolling up still works — copy-mode reaches tmux's own history from there — but there is no deeper on-demand fetch yet. That's a gap, not a setting. Server-side history is raised to 50 000 lines at attach and the client keeps 50 000 per pane; the 2 000 is only the replay depth.

If the swipe conflicts with what you run, the ⇅ Scroll history chip does the same job. It's a builtin that starts outside the shortcut bar.

The prefix key

Over SSH + tmux, Ctrl-b does not reach tmux

Keystrokes are delivered per-pane as a tmux command that injects bytes into the program running there:

send-keys -t %41 -H 1b 5b 41

Nothing on that path consults tmux's key table, so a typed ^B reaches your shell or your agent as ^B — it doesn't open the prefix. Navigate with the breadcrumb, the sheets, the home tree and the swipe. To send a control key from the software keyboard, use the ctrl chip: it arms one-shot, and the next key goes out as its control code.

Over mosh + tmux the opposite is true. The screen is tmux's own UI, so Ctrl-b drives it as it does on your desktop — which is why the breadcrumb there collapses to user@host · tmux. One sharp edge: a custom shortcut scoped with Only in tmux keys off the SSH + tmux controller, so it does not appear on a mosh + tmux session.

Agent status on tmux

Without the hooks it guesses. With them it knows.

herdr reports agent state as a protocol field and needs nothing installed. tmux has no such field, so Offhook offers a hook install — and is honest that it's an install you perform, on a config it backs up first.

Open the sheet

Settings → Install agent hooks. Pick your agent: Claude Code, Codex, Gemini CLI, Qwen Code, Qoder, Factory or CodeBuddy. The row is hidden on herdr, which doesn't need it.

Run the one-liner

Run in terminal, or Copy command and paste it yourself. It backs up your config, writes ~/.offhook/offhook-stamp.sh, then merges four hook groups.

Run a turn, then Re-check

Hooks fire during an agent turn, so nothing appears until one runs. Then Re-check confirms: "Hooks are live."

What the hook writes

Four tmux pane options on $TMUX_PANE. That's the whole mechanism — no socket, no daemon, no callback to Offhook.

tmux set -p -t "$TMUX_PANE" @offhook_state working   # or attention | done
tmux set -p -t "$TMUX_PANE" @offhook_agent claude
tmux set -p -t "$TMUX_PANE" @offhook_since 1754630400
tmux set -p -t "$TMUX_PANE" @offhook_title "Bash: npm install"

UserPromptSubmit and PreToolUse → working; Notification (Claude family) or PermissionRequest (Codex) → attention; Stop → done. The script opens with [ -n "$TMUX" ] || exit 0 and always exits 0 — it stamps a pane, it can't block or slow the agent. Re-running de-dupes instead of stacking.

Offhook reads it back with one command every two seconds while attached. An unset option expands to nothing, so an unstamped pane returns %5|||| and falls through to the guess below:

list-panes -a -F '#{pane_id}|#{@offhook_state}|#{@offhook_agent}|#{@offhook_since}|#{@offhook_title}'
What you lose without it

The fallback is a guess, deliberately narrow

With no hooks, Offhook reads the pane: sustained output under a known agent command for 2 s → working; a terminal bell (BEL) → needs you; 4 s of quiet → done, gone after 25 s.

  • Only claude, codex, gemini, qwen, qoder, factory, codebuddy, aider, goose and opencode are promoted by output. Builds, tail -f, dev servers and vim never are — a BEL is the one thing that bypasses the filter
  • No detail line. "Bash: npm install" comes from @offhook_title; the guess has no idea what the agent is asking
  • No "finished" ping. That fires only on a real Stop stamp — four seconds of quiet is too fuzzy to buzz a phone for

Limits to know before you rely on it

  • Gemini CLI exposes no Notification event, so "needs you" falls back to the bell there.
  • No jq on the host means no title. The state still stamps.
  • Run in terminal refuses when the active pane is already running an agent — the command would be typed into the agent's input box. Switch to a shell pane first.
  • There's no Agents list on the home screen for tmux. That section exists only on herdr: hook coverage is only as complete as what you installed, and a list that silently omits half your agents is worse than no list.
  • Agent status doesn't reach the island over mosh + tmux at all. The -CC sidecar drives the breadcrumb and the sheets; it isn't wired to the agent monitor. Use SSH + tmux if you want your phone to tell you an agent is waiting.
  • iOS suspends the app and the two-second poll stops with it. State doesn't update again until you return. There is no Offhook server and no push. The Live Activity marks itself stale after 120 seconds and says paused rather than showing a frozen "working".

On your server

It attaches to what you have. It doesn't leave it untouched.

Offhook never creates or restyles your sessions. But "changes nothing" would be a lie — here is the complete list of what it does change while you're connected.

Global

history-limit

tmux set -g history-limit 50000 runs before every attach, on the SSH path and the mosh sidecar. Server-wide; tmux applies it to panes created afterwards.

Per window

Size pinning

While you view a window, resize-window -x -y pins it to the phone's grid so full-screen programs reflow. Another client on that window gets the phone's width meanwhile.

Handed back

…and unpinned

On leaving the window, on background, and on disconnect. Plain resize-window -A isn't enough — it re-pins at "largest".

Left as is

Zoom

The active pane stays zoomed after you leave. Deliberate: the split layout is yours, and prefix z restores it anywhere.

Transient

copy-mode

Entered and cancelled as you scroll and type, plus a one-shot cancel of a stale copy-mode the first time a pane is seen after attach.

mosh only

The status bar

On the sidecar path the attached session gets status off for the duration, restored on switch or disconnect. Over SSH + tmux nothing about your session's appearance is touched.

The other half of the rule: another client moving its window never drags your view along unless the window you're on is gone. And if a desktop client on window-size latest fights you over the size, Offhook backs off — three reclaims within five seconds and it pauses for five. A stable screen, at the cost of the desktop winning for a moment.
