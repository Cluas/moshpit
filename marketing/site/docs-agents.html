Answering agents from the lock screen

An agent on your server stops and asks for permission. This page traces the whole path: how that state gets to your phone, exactly what each button types back, which settings change it, and the point where iOS stops all of it.

The agent reports

On herdr, agent_status is a field on every pane — nothing to install. On tmux, hooks you install stamp four @offhook_* options onto the pane the agent runs in.

Offhook reads it

While Offhook is running it sweeps every tracked session every 2s. On herdr the control poll is 2s while things move, easing to 8s once the tree goes quiet.

Your tap types back

The lock-screen buttons run inside Offhook, not in the widget. Each sends raw bytes into that pane — Enter, Esc, Ctrl-C, or your text. Nothing else.

There is no Offhook server in this picture. Every alert on your phone is a local notification the running app generated from the live session. That is the trade for having nothing in the middle, and it has a cost you should know before you rely on it.

Read where this stops working before you decide to walk away from your desk.

Source of truth

Two ways a state reaches the phone

Both paths end in the same four words — working, needs you, done, idle — but they get there very differently, and the difference is visible.

herdr

a protocol field · nothing to install

  • Agent state is a protocol field: every pane carries it, and nothing goes on the host
  • blocked becomes "needs you"; working, done and idle map straight across
  • Anything else, unknown included, produces no state at all — nothing lights up without cause
  • Settings hides the hook installer here, because there is nothing to install
  • No transition timestamp, so the timer starts when Offhook first sees the change, not when it happened

tmux

hooks you install, once per agent

  • One command, offered in Settings: Install agent hooks, with Run in terminal, Copy command and Re-check
  • Covers Claude Code, Codex, Gemini CLI, Qwen Code, Qoder, Factory and CodeBuddy
  • Safe to run twice: it backs up your config, always exits 0 so it can never block the agent, and de-dupes its own hooks
  • Without hooks it guesses from output and the terminal bell — described below as the guess it is

What the tmux installer writes

One shared script, plus a registration in the agent's own config file. Your config is copied to a timestamped .offhook.bak before anything changes.

# written once, shared by every agent
~/.offhook/offhook-stamp.sh

# registered in the agent's own config (Claude Code shown)
~/.claude/settings.json
~/.claude/settings.json.offhook.bak.1754630400   <- your file, first

# hook event → the state it stamps
UserPromptSubmit   →  working
PreToolUse         →  working
Notification       →  attention      (Codex: PermissionRequest)
Stop               →  done

Each fire stamps four tmux pane options. Offhook reads them all back with a single list-panes -a per poll — one round trip, however many panes you have.

@offhook_state   attention
@offhook_agent   claude
@offhook_since   1754630400        (unix seconds)
@offhook_title   Bash: npm install --save-dev vitest    (80 chars max)

The title is the only part that can fail on its own. It is derived from the hook's stdin with jq, so on a host without jq you still get state, just no "what is it asking" line. It is cleared on done, so a stale one never lingers. One more gap worth knowing: Gemini CLI exposes no Notification event, so on Gemini that hook group is inert and attention falls back to the bell.

No hooks on tmux? Then it is a guess, and it says so

With nothing installed, Offhook watches pane output and the terminal bell. It is deliberately conservative: a row appears only for a known agent command — Claude Code, Codex, Gemini, Qwen, Qoder, Factory, CodeBuddy, aider, goose or opencode — and only after two seconds of sustained output. A build, a tail or a running server never gets promoted. Four seconds of quiet flips it to done; 25 seconds later the row disappears.

What the guess cannot do: it produces no detail line — the Bash: npm install text exists only on the hook and herdr paths — and its idea of "done" is too fuzzy to send the finished ping. A bell always surfaces, even from a shell prompt. And the moment a real hook stamp arrives for a pane, the guess stops being consulted for it.

The heuristic is never applied to herdr. herdr reports the truth; a guess layered on top would only be a worse second opinion competing with it.

The surface

What actually lands on the lock screen

One Live Activity for the whole app, not one per connection. It carries up to four agents, most urgent first: needs you, then working, then done, then idle.

The header counts Offhook on the left, and on the right a summary built from live counts — 1 needs you · 1 working. Finished agents are counted there too.

The urgent one gets the buttons Dot, command, host · session · window, what it is asking, and the controls. Everything below it collapses to a header line — because iOS clips a tall activity, and what fell off the bottom was exactly the second agent's Allow and Deny.

The timer runs live Working and needs-you rows carry a counting-up timer from the moment the state changed. Done and idle show the word instead.

The same card as a text diagram, so the shape is unambiguous. The second agent has no detail line and no buttons, by design:

Offhook                              1 needs you · 1 working

●  claude                                       04:11
   work · main · 2:rednote
   Bash: npm install --save-dev vitest
   [ Allow ]  [ Deny ]  [ yes ]  [ continue ]

●  codex                                        1:22:07
   work · api · 1:server

In the Dynamic Island

The pill shows one agent — an iOS limit, not a choice. When several are live, a Switch button in the expanded view cycles which one the pill is showing. Tapping the activity anywhere deep-links straight into that pane.

  • Compact: the state dot on the left. On the right, an amber ! for one blocked agent, the amber count for several, a live ticking teal timer when exactly one agent is working, or a checkmark when one is done.
  • Expanded: the headline agent with its detail line, then up to two more as real rows with their own dots and timers, then +N more, then the controls.

needs you Amber owns the pill whenever anything is blocked on a human. One agent gets the exclamation mark; several get the count.

working A single working agent gets a live timer instead of a label — a thinking agent and a stuck one should not look alike.

The four colours never change

These are fixed by meaning, not by your Appearance settings. If they followed the theme accent, someone who picked an amber accent would watch "working" and "needs you" become the same colour.

StateOn screenColourWhat it means
working working + live timer teal Actively doing something
blocked / attention needs you + live timer amber Waiting on a human — approval, question, permission prompt
done done green Finished its turn, not yet looked at
idle idle dim white Never lights the island — a quiet row on Home only

The control surface

What each button actually sends

Raw keystrokes into the agent's pane. That is the entire mechanism — no API call, no agent SDK, no chat channel.

ButtonSent into the paneAppears whenWhere
Allow 0x0d — a bare Enter needs you Activity + notification
Deny 0x1b — Esc needs you Activity + notification
yes / continue the word, then Enter needs you Live Activity only
Reply your text, then Enter needs you · done Notification only
Stop 0x03 — Ctrl-C working on the card; on every needs-you alert Activity + notification

Allow and Deny are tuned for Claude Code's permission prompt, where the affirmative option is default-highlighted and Esc cancels — which also fits the great majority of terminal yes/no menus. Say it plainly: they are blind keystrokes. Offhook does not read the prompt to check which option is highlighted. yes and continue type into the pane, not into a chat. An empty Reply still submits a lone Enter.

Two guards, because a silent failure is the worst outcome

  • Prompt already gone. If Offhook knows that pane has already left needs-you, an Allow or Deny is not sent, and a notification says so. Answering a prompt that no longer exists could approve a newer, more dangerous one. If the app was relaunched and has no record, the keystroke does go through — no record never blocks.
  • Not delivered. If the transport is dead, Offhook force-resumes and retries. If it still cannot reach the pane it tells you: "Your tap didn't reach the agent — open Offhook and answer there." A lock-screen Allow that silently fails is the one outcome worth interrupting you for, because otherwise you walk away believing you approved.

On herdr there is a third step you never see. tmux can address a pane directly with send-keys -t; herdr cannot — it types into whatever pane is focused. So Offhook focuses the target first, waits for the frame channel to actually flip, and only then writes. If it cannot get focus within five seconds it reports failure rather than guessing. This exists because in review, with two agents running, a lock-screen Allow could land in the other agent's pane.

Alerts

The notifications, and how to tune them

All of them are local — generated on-device from the live session, with no server involved. iOS asks for permission the first time you connect with Notifications on, not at first launch.

What gets posted

  • Needs you. Title is the agent (claude); body is what it is asking plus where, or the generic "Agent needs your input — host · session · window" when no title was captured. One per pane, so a newer one replaces the old instead of stacking. Actions: Allow, Deny, Reply, Stop.
  • Finished. ✓ claude finished with the location as the body, and a Reply action so you can fire the next instruction without opening the app. This one is hook-driven only — the tmux guess's idea of "done" is four seconds of quiet, which is not a good enough reason to buzz your pocket.
  • Withdrawn automatically. When a pane leaves needs-you, its delivered alert is pulled off your lock screen. A stale "needs you" invites answering a prompt that is gone.
  • Quiet when you are already there. If you are looking at that exact pane, the notification goes to the list with no banner and no sound. On any other screen it still banners.

Settings → NOTIFICATIONS

Four toggles, all on by default.

ToggleIn the appTurning it off
Notifications Alert when an agent needs you No pings at all — the Live Activity keeps working
Live Activity Show agent session status in the Dynamic Island No lock-screen card and no pill — notifications still fire
Alert sound Play a sound when the agent needs you Both the needs-you and finished pings go silent
Show detail on lock screen Display what the agent is running/asking — off keeps it private The what disappears from the card, the widget and the notification body. State still shows.

Two more rows live in the same group: How notifications work, which says the same thing this page does, and Install agent hooks, which appears only on tmux connections. If you turn both Notifications and Live Activity off, Offhook stops tracking the connection entirely — nothing is watched and nothing is polled.

The Agent Status widget

Separate from the Live Activity, and worth knowing it behaves differently. Add it as a small or medium home-screen widget, or as a Lock Screen accessory — rectangular, circular or inline. It receives no pushes: it reads a snapshot the app writes on every sync, on iOS's own refresh schedule. Small and medium prefer the detail line over the location, because Bash: npm install tells you more than work · 2:rednote. Medium shows three agents. Once the snapshot passes three minutes old, every dot dims to grey and the summary line becomes paused — open Offhook.

Where this stops working

Offhook has no push server. Most of what follows is downstream of that one decision, and none of it is fixable in the app.

Background

Suspended means frozen

When iOS suspends Offhook, the 2-second sweep stops. Verified on device: with the app backgrounded, flipping an agent from blocked to working did not move the island until we returned and one poll ran.

Honesty

It admits it instead of lying

The Live Activity carries a 120-second staleness horizon. Past it, iOS marks the card stale and it renders paused — open Offhook to refresh rather than a frozen "working" that would be untrue.

Focus

It will not break through Focus

The needs-you alert asks to be time-sensitive, but Offhook does not ship the time-sensitive entitlement. iOS delivers it as an ordinary alert, so Do Not Disturb silences it like anything else.

One at a time

Only the urgent one gets buttons

Four agents ride the activity at most; the expanded island shows the headline plus two rows and then +N more. Only the first has controls, and only one fits the pill — the rest need the Switch button.

Keystrokes

Allow does not read the screen

Enter and Esc, sent blind. If a TUI you use puts the destructive option under the highlight, Allow presses that. The stale-prompt guard blocks a tap only when Offhook knows the prompt is gone.

Mosh

Mosh + tmux has no agent status

Mosh cannot carry tmux control mode or herdr's frame protocol, so over Mosh those run their own terminal UI. On a Mosh + tmux connection the island and its notifications are not driven at all. Mosh + herdr does work — a lightweight SSH sidecar carries the control plane.

Plain SSH

No multiplexer, no agent status

A connection with Multiplexer set to None has nothing to read state from. Agent status needs tmux or herdr; that is the whole reason the picker exists.

herdr

Up to 8 seconds behind

herdr's CLI exposes no event subscription a phone can reach, so Offhook polls: 2 seconds while things move, 8 once the tree settles. Changes you make on your laptop can lag that long. Actions taken in the app refresh immediately.

herdr

Direct attach is exclusive

One client owns a pane at a time. Two Offhooks on the same pane will fight, each reclaiming it within about two seconds. That is inherent to herdr's direct attach, not something the app can smooth over — it backs off and tells you when it happens.

Smaller ones, for completeness. herdr 0.7.3 — the current Homebrew stable — reports no pane command or agent name, so the breadcrumb falls back to pane N and idle agents never grow a row there. herdr only sees its own panes: an agent you started in a plain Terminal on the host is invisible to it. After an app relaunch, Offhook has no record of when a state began, so rows show no duration rather than inventing one. And the button titles themselves — Allow, Deny, Reply, Stop — render in English today regardless of your language.

Questions

The ones that come up first

Do I have to install something on my server?

On herdr, no — agent state is a protocol field. On tmux, yes if you want precise state and the "what is it asking" line: Settings → Install agent hooks shows you the exact command, backs up your config, and runs only when you tap Run. Without it, Offhook falls back to watching output and the terminal bell, which is a guess and is described as one.

Will it wake me up when Offhook is closed?

No. Every alert comes from the running app reading the live session, and iOS suspends that. State stops updating until you come back. There is no push server to fix this with — the same reason there is no account and nothing in the middle.

Can I hide what the agent is asking?

Turn off Show detail on lock screen. The Bash: npm install … line disappears from the Live Activity, the widget and the notification body. You still see which agent it is, where it is, and whether it needs you.

What if I tap Allow and the prompt already moved on?

If Offhook knows the pane left needs-you, nothing is sent and it tells you the prompt is gone. If the app was relaunched and has no record, the Enter does go through — which is why the notification is withdrawn from your lock screen as soon as the prompt clears.

Does the Dynamic Island show all my agents?

One at a time in the pill — iOS renders a single activity there. The expanded view shows the headline plus two more and then a count, and the Switch button rotates which one the pill is on. The Home screen's Agents section is the full list.
