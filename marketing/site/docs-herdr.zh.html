文档

用 herdr

herdr 是专门为 CLI coding agent 写的多路复用器。连 herdr 的时候， Moshpit 不用你在主机上装任何东西，就知道每个 agent 在干什么。这一页讲安装、术语、键位、 Agents 区、隔离任务——最后一节讲清楚哪些事它做不到。

herdr 是一个 Rust 单二进制。Moshpit 支持它，是因为它把三件苦活从手机搬到了服务端——而 tmux 那条路上， 这三件事还得 Moshpit 自己扛。

Agent 状态

协议里的一等字段

每个 pane 上都有 agent_status，并自动从 pane 上卷到 tab、再到 workspace。tmux 上要你先装 hook，往 @moshpit_* 里写状态。

滚动

服务端决定去向

terminal.scroll 是协议动作，一次滑动该变成 mouse report 还是翻 scrollback 由 herdr 判。tmux 上是 Moshpit 自己读 #{mouse_any_flag} 再猜。

尺寸

只影响自己那个 pane

直连客户端的 resize 只打到自己那个 pane 的 PTY。tmux 上手机一连，整个 window 对所有客户端都被拉小——Moshpit 那套钉窗口尺寸的机制就是为此存在的。

它是 tmux 的另一种选择，不是替代品。两者是独立的服务器， 装的是毫不相干的会话。选哪个按连接决定，Moshpit 绝不替你换成另一个——herdr 没装就默默去 attach tmux，等于把别人的活儿端到你面前说这是你的。

版本。设计基准是 herdr main / v0.8.0，protocol 19； 实机验证跑的是 0.7.3，protocol 16——当时 brew install herdr 装到的就是它， 差了三个协议版本。解码器按「字段缺了就降级这一处细节、绝不让整份读取失败」写； 0.7.3 上会少点什么，这一页会明说。

安装

先装上，再按连接选它

herdr 不在任何 Linux 发行版仓库里，它自己的 packaging 只覆盖 Windows。 所以这里没有 apt-get 那一行可给，Moshpit 也拒绝硬凑一条—— 凑出来的命令只会以「找不到软件包」收场，而用户会以为是 App 的 bug。

在主机上装 herdr

有 Homebrew 就用 Homebrew，没有就用官方脚本。脚本把二进制放进 ~/.local/bin，并且刻意不动你任何 rc 文件。

在连接里选 herdr

Add Connection → ADVANCED → Multiplexer → herdr。 按连接存，不做全局默认——你的每台主机装的东西本来就不一样。

连上去

主机上没有？横幅直说，并给出 Install Assist。这时你得到的是裸 shell， 不会被偷偷换成 tmux。

# Moshpit 按探测到的主机情况给出其中一条
brew install herdr
curl -fsSL https://herdr.dev/install.sh | sh

Moshpit 探测和启动用的是同一套额外 PATH，其中包含 $HOME/.local/bin——否则 Install Assist 刚给你的那条命令， 会在下次连接时变成「herdr: command not found」。填了 Custom herdr Path 的话， 它会被原样信任，同时绕过这两者。

ADVANCED 那一组的脚注，原话：“tmux and herdr hold separate, unrelated sessions. If the host doesn't have the one you pick, Moshpit says so and drops to a plain shell — it never quietly attaches the other. With Mosh, herdr runs its own terminal UI; native rendering needs SSH.”

  • 主机没装——横幅 “herdr not found on this host — plain shell session.”， 动作 Install herdr。Install Assist 开头是所有安装流程共用的一句： “Moshpit never installs anything silently. Run the command below in your shell — sudo and its output stay fully visible.” 装完点 Re-check 会翻成「已安装，重连即可」。
  • 服务器没在跑——空态 “No herdr workspaces” / “This server has no running workspaces. Moshpit only attaches — create the first one to start.”， 按钮 Create Workspace，执行中读作 Creating…。

那个按钮是 Moshpit 里唯一会拉起 herdr 服务器的地方 （nohup herdr server，然后 workspace create --focus—— 干净启动的服务器是零个 workspace，所以必须两步）。有一处例外要说清楚：Mosh 那条路上 Moshpit 是往 shell 里敲一个裸 herdr，而它在服务器没跑时确实会顺手建一个 workspace。这一点被接受，是因为那个终端里跑的本来就是 herdr 自己的界面， 你看到的和自己敲 herdr 一模一样。

这里 SSH 比 Mosh 拿得多

Mosh 传的是渲染完的屏幕差分，会把行分帧毁掉——和 tmux -CC 上不了 mosh 是同一个原因。所以 herdr 的帧协议只在 SSH 上跑。

连接方式主机有 herdr你得到什么
herdr + SSH有 原生表单 + 单窗格原生渲染，满屏宽
herdr + Mosh有 herdr 自己的 TUI（侧边栏吃掉约三分之一屏宽）， 另加一条 SSH sidecar 让表单照常可用
选了 herdr，主机只有 tmux没有 横幅 + Install Assist，绝不静默切换
选了 herdr，两个都没有没有 裸 shell + 横幅

Agent 状态

为什么这里的状态是白送的，tmux 上却要装 hook

在 tmux 上，「哪个 agent 在等我」是推断出来的：你先装 hook， hook 往 pane option 里写状态，没装 hook 的 pane 只能靠输出和响铃猜。 在 herdr 上这是一次查询——agent_status 本来就在每个 pane 上。

herdr agent_statusMoshpit 显示成 出现在哪
working 青色点 · 工作中 · 实时计时 主页 · 面包屑 · 灵动岛 · 锁屏
blocked 琥珀点 · 需要你 主页 · 面包屑 · 灵动岛 · 锁屏
done 绿色点 · 已完成 主页 · 灵动岛。不会把整个窗口点亮成琥珀
idle 不给点——一行安静的暗行 只在主页。永远不点亮锁屏
unknown / 没有 什么都不显示—
  • 这三个颜色是写死的，不跟你的强调色走——否则把强调色调成偏琥珀， 「工作中」和「需要你」就会变成同一个颜色。
  • herdr 连接下，设置里的 Install agent hooks 那一行会隐藏， 只用 herdr 的人不会被劝去装 tmux 的 hook。
  • tmux 那套「看输出和响铃猜」的启发式不会叠到 herdr 上：真相已经报上来了， 再加一个猜测只是一个更差的第二意见。
  • 已实机验证：herdr pane report-agent --state blocked 和 --state working（herdr 自家集成用的同一个接口），主机上零安装。
  • 可选、而且更权威：herdr integration install claude 让 agent 自己上报， 而不是靠 herdr 读屏幕。不装也能用。

blocked → 需要你 琥珀色，超过一个时带计数。锁屏卡片上是 Allow、Deny 和两条快捷回复。

working → 青色计时 在想事情的 agent 和卡死的 agent 不再长得一样。working 只给 Stop。

在锁屏上回答

herdr 上要先把焦点挪过去

tmux 能用 send-keys -t 直接寻址某个 pane；herdr 的帧通道只会打进 它当前 attach 的那个 pane。所以 Moshpit 先聚焦目标、等 retarget 收尾，再写入 ——切换途中入列的按键会掉进裸 shell 里死掉。聚焦不到就明确失败， 通知层退回「打开 App」，而不是假装你那一下点成了。

另一种可能是复查时抓到的：两个 agent 同时在跑时， 锁屏上的 Allow 可能变成另一个 agent 的回车。

术语

是 workspace 和 tab，不是 session 和 window

内部只有一份数据模型，两种多路复用器共用，只在展示层翻译。 但「模型能复用」不等于「tmux 的词也该复用」：herdr 里明明叫 tab 的东西， 界面上读到 “Kill Window”，每看一眼都是一次小小的税。

herdridtmuxMoshpit 里叫
workspacew1 session $0 Workspace / Workspaces
tabw1:t1 window @0 Tab / Tabs
panew1:p1 pane %0 Pane / Panes
  • 删除的动词跟着 CLI 走：tmux 是 Kill，herdr 是 Close——因为 herdr 的命令 就是 workspace close / tab close / pane close。
  • 树的区标题读 WORKSPACES；顶部统计芯片两个控制面都数—— 它以前写死 TMUX，herdr workspace 活着也报 0。
  • 显示成 “Tab 1”，不是 “1: 1”——herdr 默认拿序号给 tab 命名，一棵这样的树就是 一墙数字。tmux 那种以命令命名的 window 仍然读作 2: logs。
  • 重名时补 “~ · w4”——herdr 用 cwd 给 workspace 命名，四个都在 ~ 的会全读作「~」。重名时行尾补原始 id：那是 herdr CLI 寻址用的把手，不是装饰。

键位

⌃ b q 在 herdr 里是断开会话。这是个真坑。

两边默认前缀键都是 Ctrl-b，所以现有的前缀处理和快捷键栏原样能用。 但有三个键对不上，其中一个会把你踢下线。

Select Pane 表单以前在 herdr 连接上印的是 ⌃ b q。 在 tmux 里那是列窗格，在 herdr 里那是 detach——App 在印一个会把用户会话丢掉的键。 现在印的是 ⌃ b v，也就是分屏：herdr 根本没有「把窗格列出来」这个键， 硬编一个出来比承认没有更糟。

⌃ b s 在 herdr 里没有绑定（workspace 是 ⌃ b w）； ⌃ 1-9 在 tmux 里是按编号跳窗口，herdr 则用 n / p 一步一步走。

表单tmux 印herdr 印
Sessions / Workspaces⌃ b s ⌃ b w
Windows / Tabs⌃ 1-9 ⌃ b n/p
Panes⌃ b q ⌃ b v

快捷键栏里那个「只在多路复用器里显示」的开关，现在把 herdr 也算进去了。 它以前由「有没有 tmux controller」喂，herdr 上恒为 false——结果你勾了这个选项的键， 偏偏在你唯一想要它的连接上消失。

主页

Agents 区回答的是你真正想问的那个问题

主机 → 会话 → 窗口 → 窗格这四层树回答的是「它在哪」，不是「谁在等我」。 herdr 连接的主页会在 workspace 树之上加一个 AGENTS 区， 长在同一张卡、同一条滚动里。没有 Agents 页，没有底部 tab 栏，不新增导航轴。

仅 herdr 连接

它是一次投影，不是又一次轮询

每一行都来自树和灵动岛本来就在读的那份 snapshot，额外远端调用为零。

  • 排序：需要你 → 工作中 → 已完成 → 有名字的 idle 排最后
  • 同级按名字、再按 pane id 破平，两次轮询之间不会重新洗牌
  • 点一行的效果和点树里的窗格完全一样——只有一个入口
  • 标题栏——AGENTS 加计数芯片，右侧琥珀色的 NEEDS YOU （多于一个时读 2 NEED YOU），再加一个 +。
  • 一行——agent 名、workspace · tab、状态点、行尾的已持续时长。 状态点带 VoiceOver 文字，颜色不是唯一的通道。
  • 时长只到分钟——now、2m、1h 12m， 永远不显示秒：背后的轮询最粗到 8 秒。它和锁屏计时器读同一只钟，两边永远不会打架。
  • 一行得有出现的理由——要么有活的信号，要么是一个带 agent 名字的 idle 状态。匿名的安静窗格什么都不产生。有名字的 idle 是暗行、无光点、排最后： 「一个停在提示符前等活的 claude」和「什么都没跑」是两个不同的答案。
  • 空态——“Nothing running — start a task to isolate one”。 一个 agent 都没有时标题栏也照样在——把整个区藏起来就等于藏掉了那个 +， 第一个任务就永远建不出来。

隔离任务

New Agent Task：一个 git worktree、一个 workspace、一个 agent

AGENTS 标题栏里的 + 打开一张四个字段的表单。填完它会在主机上 建一个真的 git worktree，并把 agent 起在里面。你自己的工作区一动不动。

表单

Repo、Branch、Agent、第一条消息

TASK 组脚注：“Creates a git worktree on the host, then starts the agent inside it. Your working tree is untouched.”； FIRST MESSAGE 组脚注：“Optional. Sent to the agent once it's running — leave blank to type it yourself.”

执行中 Start 变成 Starting…。大仓库 checkout 要几十秒， 一个没有进行中状态的按钮看起来就是坏的。

herdr worktree create --cwd '<repo>' --branch '<branch>' --label '<branch>' --focus --json
→ 新 worktree + 新 workspace + 一个 cwd 已经在检出目录里的窗格，
  位置是 ~/.herdr/worktrees/<repo>/<branch>

herdr pane run '<root_pane>' '<agent>'   # 把命令敲进去并回车
herdr agent send '<root_pane>' '<prompt>'  # 你填了才发，2 秒之后

没有用 agent start：实测它不继承 worktree 的目录， 新窗格落在发起 CLI 的那个 cwd 里。而 worktree create 已经给了一个目录正确的 窗格，直接 pane run 更简单，少一个失败点。所有字符串进 shell 之前都做了 POSIX 单引号包裹。

Repo 列表是从哪来的

herdr 不管「你有哪些仓库」，所以 Moshpit 自己去找——而且是两条命令并发跑， 这是有意的。窗格 cwd 用 git -C <cwd> rev-parse --show-toplevel 反查， 小、快、排在前面；旁边并行一次 $HOME 扫描 （find -L "$HOME" -maxdepth 4，prune 掉 Library、 node_modules、媒体目录和隐藏目录，按 mtime 取前 40）， 客户端预算 8 秒。熔成一条命令的版本在真机上翻过车：iCloud 同步的 $HOME 把 find 卡过 25 秒，随后整条链路失联， 表单最后只剩一个「Other…」。

残留的限制：预算超时之后，远端的 find 还会继续跑完—— exec 通道发出去就收不回来——那份 prune 列表就是它的全部上限。菜单在扫描时读 “Looking for repositories…”，空手而归时读 “None found — no panes in repos, and nothing under ~”，最后一项永远是 Other…。

  • agent 列表来自 herdr server agent-manifests --json。默认优先 claude，其次 codex——按字母序曾经在一台真实主机上把默认值 选成了 agy。
  • 分支名在手机上先校验，不合法就一个请求都不发（不许空格、不许 ..、 不许以 .lock 结尾、不许 ~ ^ : ? * [ \ 等）。 原因就地显示在字段下方，所以变灰的 Start 不会看着像坏了。
  • herdr 自己的错误原文照抄——branch 'fix-scroll' already exists 不需要翻译。
  • agent 的参数不替你决定。跑的是 manifest 里的默认命令， --dangerously-skip-permissions 之类要你自己敲。

删 worktree 要过两道确认

长按 workspace 行 → Remove Worktree，只在真的是 linked worktree 的 workspace 上出现。第一条命令绝不带 --force：

1 · “Remove the worktree for <name>?”——“Deletes the branch checkout under ~/.herdr/worktrees. <repo> itself is untouched.” Remove / Cancel。

2 · 只有当 herdr 回 dirty_worktree_requires_force 时才弹第二道 （实测它会拒绝，并且文件一个不动）：“<name> has uncommitted changes”—— “Those changes exist nowhere else. Removing the worktree throws them away.” Delete anyway / Keep it。只有这一下才会加上 --force。

这是 herdr 自己的安全网，不是我们发明的。未在设备上验证：长按菜单本身—— idb 驱动不了 SwiftUI 的 contextMenu 长按，所以「菜单 → 对话框 → 对话框」这一段只有编译 和单测保证，没有设备录像。

限制

做不到的事，都在这一节

下面大部分是真机跑出来的，每一条都会改变你该怎么用它。

外部改动最多滞后 8 秒。 Moshpit 每 2 秒轮询一次 herdr api snapshot，树不再变化后退到 8 秒。 App 内的操作立即刷新；你在笔记本上、别的客户端上，或者 agent 自己改状态， 都要等一轮轮询。这个 ±8 秒的误差，正是 Agents 区从不显示秒的原因。

没有推送，也没有 Moshpit 服务器。 所有提醒都是正在运行的 App 生成的本地通知。herdr 的 socket 上确实有事件订阅， 但 CLI 没有 subscribe 子命令，手机也打不开主机上的 Unix socket。轮询是唯一可用的机制。

iOS 把连接挂到后台后，agent 状态就停止更新，直到你回来。 实机验证：退到后台，把一个 pane 从 blocked 改成 working，灵动岛纹丝不动； 回到前台一轮轮询之后才翻。这是「不做远程推送」这个产品决定的必然结果，tmux 路径同理。 Live Activity 带 120 秒的过期时间，所以锁屏会说「已暂停」， 而不是挂着一个冻住的「工作中」。

直连 attach 是按 pane 独占的——两个客户端连同一个 pane 会打架。 Moshpit 必须 takeover，因为每次重连都会撞上自己的旧通道；之后两个直连客户端会各自约每 2 秒重新夺一次。这在客户端消不掉。Moshpit 至少能认出来：30 秒内三次非预期断开会触发 30 秒暂停并显示 “Another client is using this pane — retrying shortly”， 画面恢复后自动消失。

未验证：笔记本上开着 herdr 自己的 TUI，同时手机连上来。 TUI 客户端不占 attach 名额，理论上这个组合安全。但没测过，所以不做保证。

一次只渲染一个窗格。 原生渲染就是单窗格满宽，这是有意的——每多一个窗格就要多一条 SSH 通道。

没有全量 scrollback。 herdr 的读取接口只有 visible / recent / recent-unwrapped / detection； 而且它的帧是逐格绝对定位的重绘，不是追加式字节流，本地也攒不出有意义的 scrollback。 历史浏览走服务端翻页。

herdr 0.7.3 的 pane 上没有 title、agent 名和 label。 窗格的「命令」因此是空的，面包屑第三段兜底成 pane N——这是有意保留的， 因为面包屑一旦消失，就把进 Select Pane 表单的唯一入口一起带走了。 另外，拿不到 agent 名，0.7.3 上 idle 行根本不会出现。

没有 tmux 那种 layout 字符串，窗格版面是推出来的： 读窗格自己上报的几何，宽度都一样是纵排，高度都一样是横排，否则当网格。 目标是每个窗格都在屏幕上、都能点，并且真正的活动窗格被标出来，不是逐像素还原布局。

herdr pane focus 只接受方向，不接受 pane id——0.7.3 和 0.8.0 都一样。 唯一能按 id 聚焦的是 herdr agent focus <pane_id>， 它对普通 shell 窗格会报 agent_not_found，但焦点确实会移动： 服务端先聚焦，再在构造响应体时失败。Moshpit 故意把这个错误吞掉。 这是整个集成里最脏的一处，代码注释里也是这么写的。

不支持具名 herdr session。 herdr 可以用 --session / HERDR_SESSION 跑多个互相独立的服务器， Moshpit 只连默认那个 socket。更麻烦的是：App 里目前哪儿都没写这件事—— 你要是把主机拆成了多个具名 session，Moshpit 只看得见其中一个，而且不会给你任何提示。

只看得见 herdr 托管的窗格。 实测踩过：Terminal.app 里跑着一个 claude，herdr 的五个窗格全都空转， 于是这个区正确地显示「Nothing running」，而用户确信有东西在跑。 herdr 是 runtime，不是进程扫描器——想让 agent 出现， 要么用 New Agent Task 起它，要么在 herdr 窗格里跑。

带宽和帧率从来没测过。 逐格定位的重绘走 SSH，对上 tmux -CC 的输出流，在一个疯狂刷屏的 agent 面前 谁更省字节——重绘很可能更费。在有人真的量出来之前，两个方向的性能结论都不说。

worktree 落在 ~/.herdr/worktrees/<repo>/<branch>， 不在仓库旁边，这一版也不给自定义路径。大仓库 checkout 要几十秒。 仓库不干净时 git worktree add 的行为按理没问题（独立 checkout）， 但还没验证过。
